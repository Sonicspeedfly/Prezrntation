# Сборочные скрипты — справочник

> Файлы: `assets/build-media.js` (145 строк), `assets/build-brand.js` (315 строк),
> `tools/doc-coverage.js` (132 строки) · Место в порядке загрузки: нигде. Это Node-скрипты,
> их запускают руками из корня проекта; в браузер они не попадают. В браузер попадает то,
> что они пишут.
> Связанные страницы: [deck.md](deck.md) (пакет `08b`, `loadAliceAudio()`),
> [voice.md](voice.md) (длинные дорожки, студия), [ui.md](ui.md) (видеоплеер апробации),
> [styles.md](styles.md) (рамка логотипа), [README.md](README.md) (как держать справочник полным).

## Коротко

Три скрипта, которые готовят файлы для страницы и проверяют документацию. Ни один не
нужен для показа: всё, что они делают, уже лежит в проекте.

- **`build-media.js`** — из оригиналов звука и видео делает лёгкие веб-копии: моно-mp3
  64 кбит/с для длинных дорожек, пакет из 16 реплик Элис в base64
  (`js/presentation/08b-alice-audio.js`), видео апробации в 540p и 360p и постер.
  Зритель видит результат, когда открывает питч с телефона по QR: первый экран
  грузится быстро, звук и видео догружаются потом. Нужен `ffmpeg` в `PATH`.
- **`build-brand.js`** — режет студийный логотип `assets/crystalcore-logo.svg` на два
  SVG: знак с пятью кристаллами и пылью (`assets/brand-mark.svg`) и надпись
  «CrystalCore» (`assets/brand-wordmark.svg`). В знак вшита CSS-анимация: кристаллы
  плавают, осколки и искры мерцают. Это логотип в правом нижнем углу меню.
- **`tools/doc-coverage.js`** — проверка полноты этого справочника: выписывает имена
  функций и переменных из исходников и ищет их в страницах `docs/reference/`.

## Как это работает

### `build-media.js`: три прохода

```
node assets/build-media.js            собрать недостающее и устаревшее
node assets/build-media.js --force    пересобрать всё
```

Скрипт выполняется сверху вниз, без функций-этапов: три блока кода подряд, общий
счётчик `built`. Перед каждой сборкой — проверка `stale()`: цель пересобирается, если
её нет, если её `mtime` старше источника или если передан `--force`. Сравнение только по
времени изменения файла, содержимое не сравнивается.

**1. Веб-копии длинных дорожек** ([build-media.js:48](../../assets/build-media.js#L48)).

```
assets/audio/<lang>/masters/<id>.(mp3|wav|flac|m4a|ogg|webm)   оригинал, не трогается
        → assets/audio/<lang>/<id>.mp3                         64 кбит/с, моно, 44.1 кГц
```

Обходит каждую папку языка в `assets/audio/` (сейчас есть только `ru`), берёт из её
`masters/` все звуковые файлы, кроме `deck.*` — те идут в пакет на шаге 2. Вызов:

```
ffmpeg -v error -y -i <src> -map_metadata -1 -vn -ac 1 -ar 44100 \
       -codec:a libmp3lame -b:a 64k <out>
```

| аргумент | зачем |
|---|---|
| `-v error -y` | молчать, кроме ошибок; перезаписывать без вопроса (добавляет `ff()`) |
| `-map_metadata -1` | не переносить теги исходника (название, альбом, комментарии) |
| `-vn` | выбросить видеопоток — обложку, которую mp3 может нести как картинку |
| `-ac 1 -ar 44100` | моно, 44.1 кГц. Речь ElevenLabs и так моно 44.1 кГц (комментарий в шапке) |
| `-codec:a libmp3lame -b:a 64k` | mp3, постоянный битрейт 64 кбит/с |

Почему 64 кбит/с — в шапке файла: на голосе разницы на слух уже нет, а файл вдвое
меньше. Замер на текущих файлах: `jury_act1` 500 097 → 242 041 байт, `secret_locked`
1 008 336 → 496 160 байт, остальные так же, около 2,05×. Оригиналы ElevenLabs — 128 кбит/с
(см. [voice/README.md](../../voice/README.md), раздел «Голос без записи»), отсюда ровно половина.
В [voice/README.md:147](../../voice/README.md#L147) копии названы «втрое легче» — по
замеру вдвое.

Кто читает копии: `VoiceMedia` в [15-voice-media.js:54](../../js/core/15-voice-media.js#L54)
(третья ступень после своих записей), а если копия не загрузилась —
[оригинал из `masters/`](../../js/core/15-voice-media.js#L55).

**2. Пакет реплик дека** ([build-media.js:65](../../assets/build-media.js#L65)).

```
assets/audio/ru/masters/deck.*.mp3   (16 файлов: deck.slide01–05, deck.bg01–11)
        → js/presentation/08b-alice-audio.js   window.ALICE_AUDIO = { id: "<base64 mp3>" }
```

1. `ids` — имена `deck.*.mp3` из `DECK_MASTERS` без расширения, отсортированные:
   сначала `deck.slide*`, потом остальные (фоновый пул `deck.bg*`), внутри групп — по
   алфавиту. Ключ сортировки — `"0"` или `"1"` плюс имя.
2. `newest` — самый поздний `mtime` среди этих мастеров. Пакет собирается, если он
   отсутствует, старше `newest` или передан `--force` (и если `ids` не пуст).
3. Каждый мастер перекодируется теми же параметрами, что на шаге 1, но в stdout
   (`-f mp3 -`), без промежуточного файла: `execFileSync` возвращает `Buffer`, буфер —
   64 МБ (`maxBuffer`). Буфер кодируется в base64 и кладётся в `table[id]`.
4. Файл пишется целиком из шаблона: шапка-комментарий «GENERATED FILE — do not edit»,
   `window.ALICE_AUDIO = <JSON с отступом 1>;` и строка
   `if (typeof aliceAudioArrived === "function") aliceAudioArrived();`.
5. В консоль — размер мастеров в КБ, размер JS в КБ, число реплик.

Замер на текущих файлах: 16 мастеров — 2 087 932 байт, пакет — 1 742 082 байт
(1,7 МБ, из них около 1,3 МБ — сам mp3, остальное — раздувание base64 на 4/3), gzip
пакета — 1 299 435 байт. Поэтому в разных местах встречаются обе цифры: 1,7 МБ — файл
на диске ([09-alice-stream.js:155](../../js/presentation/09-alice-stream.js#L155),
README, таблица файлов), 1,3 МБ — mp3 внутри и то, что реально идёт по сети со сжатием
(README, «Слабый интернет»).

Как пакет попадает на страницу: его нет в `index.html`. `loadAliceAudio()` в
[09-alice-stream.js:170](../../js/presentation/09-alice-stream.js#L170) через ~1,2 с после
загрузки (или по сигналу интро для жюри) создаёт `<script async src="js/presentation/08b-alice-audio.js">`.
Скрипт присваивает `window.ALICE_AUDIO` и сам зовёт `aliceAudioArrived()`
([09-alice-stream.js:187](../../js/presentation/09-alice-stream.js#L187)), которая
раздаёт base64 строкам `ALICE_STORY_LINES`/`ALICE_BG_LINES` по их `voiceId`. Тот же файл
читает студия: `bundle()` в [voice/lib.js:159](../../voice/lib.js#L159) исполняет его в
`vm` и берёт `ALICE_AUDIO`.

**3. Видео апробации** ([build-media.js:116](../../assets/build-media.js#L116)).

```
assets/video/<name>.mp4              оригинал (720×1280, 60 к/с — по шапке)
        → <name>.540.mp4             540×960, 30 к/с, CRF 27, потолок 1100 кбит/с, AAC 64 кбит/с
        → <name>.360.mp4             360×640, 30 к/с, CRF 29, потолок  450 кбит/с, AAC 48 кбит/с
        → <name>.poster.jpg          кадр на 2,5 с, 360 px по ширине
```

Источником считается каждый `*.mp4` в `assets/video/`, кроме уже собранных
`*.540.mp4` и `*.360.mp4`. Для каждого варианта из `VARIANTS`:

```
ffmpeg -v error -y -i <src> -map_metadata -1 \
  -vf scale=<W>:<H>:force_original_aspect_ratio=decrease:force_divisible_by=2,fps=30 \
  -c:v libx264 -preset medium -profile:v main -pix_fmt yuv420p \
  -crf <crf> -maxrate <maxrate> -bufsize <buf> \
  -c:a aac -ac 1 -b:a <ab> -movflags +faststart <out>
```

| аргумент | зачем |
|---|---|
| `scale=W:H:force_original_aspect_ratio=decrease` | вписать в рамку W×H с сохранением пропорций; кадр не растягивается |
| `force_divisible_by=2` | обе стороны чётные — иначе `yuv420p` не кодируется |
| `fps=30` | вдвое меньше кадров, чем в 60-кадровом оригинале |
| `-profile:v main -pix_fmt yuv420p` | профиль и формат пикселей, которые декодирует любой телефон и Safari (выведено: в коде причина не записана) |
| `-crf 27` / `29` | качество по постоянному коэффициенту; в 360p оно ниже |
| `-maxrate … -bufsize …` | потолок битрейта, буфер — 2 с потолка. CRF сам по себе даёт пики на быстрых сценах; потолок держит поток в пределах канала |
| `-c:a aac -ac 1 -b:a 64k/48k` | звук моно; в классе записана речь |
| `-movflags +faststart` | индекс `moov` в начало файла: плеер начинает играть, не дожидаясь конца файла |

Постер: `ffmpeg -ss 2.5 -i <src> -frames:v 1 -vf scale=360:-2 -q:v 6 <poster>`. `-ss` до
`-i` — быстрый переход по ключевым кадрам; `-2` — высота по пропорции, чётная; `-q:v 6` —
качество JPEG (шкала 2–31, меньше — лучше). Постер собирается один, 360 px, для всех
вариантов.

Замер текущих файлов (длительность из `mvhd`, 174,8 с):

| файл | размер | средний поток | `moov` в начале |
|---|---|---|---|
| `classroom_trial.mp4` | 73 493 598 байт | 3,36 Мбит/с | да |
| `classroom_trial.540.mp4` | 24 353 989 байт | 1,11 Мбит/с | да, 190 596 байт |
| `classroom_trial.360.mp4` | 10 490 594 байт | 0,48 Мбит/с | да, 189 976 байт |
| `classroom_trial.poster.jpg` | 28 436 байт | — | — |

Оригинал в `HD` отдаётся как есть: скрипт его не перепаковывает, но его `moov` тоже
стоит в начале. Вариант выбирает `Evidence` в [17-evidence.js:85](../../js/core/17-evidence.js#L85)
(`autoPick()`): оригинал с `file://`, `localhost` и адресов локальной сети, иначе по
`navigator.connection` или замеру скорости страницы, без данных — 360p. Подробно — в
[ui.md](ui.md).

В конце — строка `N файлов собрано` или `всё актуально`.

### `build-brand.js`: от трассировки к двум анимированным SVG

```
node assets/build-brand.js
assets/crystalcore-logo.svg  →  assets/brand-mark.svg      (кристаллы + пыль + <style>)
                             →  assets/brand-wordmark.svg  (надпись, без анимации)
```

Скрипт без аргументов и без проверки устаревания: пересобирает оба файла при каждом
запуске. Внешних программ не зовёт.

**1. Разбор.** Исходник — трассировка логотипа: 572×406 px, без `viewBox`, 74 элемента
`<path>` с заливкой, без обводок; хромированный объём собран из полупрозрачных слоёв
(70 разных пар цвет/прозрачность). Регулярное выражение берёт из каждого `<path>`
`fill`, необязательный `fill-opacity` и `d` — именно в таком порядке атрибутов. Каждый
`d` режется на под-контуры по команде `M` (`subpaths()`), для каждого под-контура
`bbox()` считает рамку. Получается `items` — 273 под-контура с цветом, прозрачностью
и рамкой. В исходнике сейчас только команды `M`, `c`, `Z`.

**2. Раскладка по областям.** `region()` смотрит на рамку под-контура и относит его к
одной из шести групп. Правила проверяются по порядку, первое совпавшее выигрывает:

| условие (координаты исходника) | группа | что это | под-контуров сейчас |
|---|---|---|---|
| `miny >= 278` | `word` | надпись «CrystalCore» | 145 |
| `minx >= 310` и центр `y < 118` | `kite` | отдельный кристалл справа сверху | 15 |
| `minx >= 310` и центр `y >= 118` | `chipR` | отдельный кристалл справа снизу | 16 |
| центр `x < 212` и центр `y < 172` | `chipL` | отдельный кристалл слева | 9 |
| центр `x < 242` и центр `y >= 172` | `base` | массивный кристалл слева внизу | 19 |
| остальное | `spire` | главный кристалл-шпиль | 69 |

Пороги подобраны руками по раскрашенной отладочной отрисовке (комментарий в шапке):
кластеризация по пересечению рамок склеивает кластер в одно целое. Шапка называет «273
sub-paths» кашей пяти кристаллов; на деле это число вместе с надписью: 128 у кристаллов,
145 у надписи. Порядок внутри группы —
исходный порядок отрисовки, поэтому полупрозрачные слои ложатся так же, как в оригинале.

**3. Пыль.** Вокруг кластера (кристаллы занимают x 176–359, y 29–262) добавляются
нарисованные с нуля элементы белой линией:

- 7 осколков `CHIPS` — `[x, y, поворот, форма]`, форма из `SHAPE`: `hex` (вытянутый
  шестиугольник), `kite` (ромб), `chunk` (неровный пятиугольник), у каждой — осевая линия
  с прозрачностью 0,4–0,45;
- 6 точек `DOTS` — `[x, y, радиус]`, кружки радиусом 0,9–1,2;
- 3 звёздочки `STARS` — `[x, y, радиус]`, крест из двух линий; при радиусе больше 3
  добавляются две диагонали длиной 0,62 радиуса с прозрачностью 0,55 (сейчас только у
  первой, радиус 4).

Каждый осколок и звезда — две вложенные группы: внешняя `<g transform="translate(…) rotate(…)">`
ставит на место, внутренняя `<g class="chip chip-N">` анимируется. По коду видно, зачем так:
CSS-свойство `transform` на элементе заменяет его атрибут `transform`, и без внешней
группы анимация сбросила бы позицию.

**4. Анимация.** Ключевые кадры не написаны руками, а генерируются из таблицы
`KEYFRAMES`. Каждый кадр — объект `{ at, o, tx, ty, r, s }`: селектор процента, прозрачность,
сдвиг по x/y в единицах SVG, поворот в градусах, масштаб. `frameCss()` превращает кадр в
CSS-строку:

```
сдвиг    = tx|ty × amp × GAIN[набор]     → translate(…px, …px)
поворот  = r × amp                       → rotate(…deg)
масштаб  = 1 + (s − 1) × amp             → scale(…)
прозрачность o — без изменений
```

Наборы и кому они достаются (`BINDINGS`: селектор, набор, длительность, задержка,
направление). Сдвиги в таблице ниже — «сырые» значения из `KEYFRAMES`, до умножения
на `GAIN`:

| набор | `GAIN` | кто | длительность, с | что делает |
|---|---|---|---|---|
| `cc-breathe` | 2,0 | `.cr-spire` | 7,5 | шпиль не плавает, а «дышит»: прозрачность 0,9→1, подъём на 1,5 ед., масштаб до 1,012 |
| `cc-drift-a` | 1,7 | `.cr-base` | 11,5 | самый короткий ход: base прилегает к шпилю |
| `cc-drift-b` | 1,7 | `.cr-chipL`, `.cr-chipR` (обратно) | 9,8 / 10,9 | дрейф вверх-вправо до 9 ед., поворот ±2,5° |
| `cc-drift-c` | 1,7 | `.cr-kite` | 13,2 | дрейф вверх-влево до 11 ед. |
| `cc-float-a/b/c` | 2,4 | `.chip-1`…`.chip-7` | 8,8–13,0 | осколки всплывают до 9 ед., вращаются на 4–12° в обе стороны, прозрачность 0,14–0,95 |
| `cc-twinkle` | 2,4 | `.spk-1`…`.spk-6` | 3,9–6,1 | точки появляются из нуля, масштаб 0,6–1,2 |
| `cc-star` | 1,0 | `.star-1`…`.star-3` | 5,4–7,6 | звезда появляется, поворачивается на 135°, гаснет |

Все анимации — `ease-in-out infinite`, у каждой своя задержка 0–4,1 с, у части —
`reverse`. Длительности разные и не кратны друг другу, поэтому картинка не повторяется
целиком через короткий период.

`STYLE` собирается так:

```
.cr, .chip, .star, .spk { transform-box: fill-box; transform-origin: center; }
.chip, .spk, .star { opacity: 0; }            ← пыль без анимации не видна
<21 привязка: .cr-spire { animation: cc-breathe 7.5s ease-in-out infinite 0s; } …>
<9 наборов @keyframes, amp = 1>
@media (prefers-reduced-motion: reduce) {
    <те же 21 привязки на наборы с суффиксом -r>
}
<9 наборов @keyframes …-r, amp = REDUCED_AMP = 0.5>
```

`transform-box: fill-box` + `transform-origin: center` — поворот и масштаб вокруг центра
самого элемента, а не начала координат SVG.

**5. Запись.** `markSvg`: `viewBox="150 0 240 292"` (`MARK_VB`), `role="img"`,
`aria-label` и `<title>` «CrystalCore», `style="overflow:visible"`, затем `STYLE`, пять
групп `<g class="cr cr-<область>">` в порядке `ORDER` и три группы пыли
(`dust-chips` — обводка 1,15, `dust-dots` — заливка, `dust-stars` — обводка 0,8).
`wordSvg`: `viewBox` — объединённая рамка группы `word` плюс отступ `pad` = 4 с каждой
стороны, округлённая до целых; одна группа `<g class="wordmark">`, без стиля. В консоль —
число под-контуров по областям и размеры файлов.

Прогон логики скрипта в памяти (запись подменена) даёт файлы, побайтно совпадающие с
лежащими в проекте: `brand-mark.svg` — 69 923 байта, `brand-wordmark.svg` — 58 483 байта.

На странице оба файла стоят как `<img>` в `.boot-brand` ([index.html:107](../../index.html#L107)),
знак шириной 78 px, надпись — 104 px; рамка, свечение и реакция на наведение — в
[styles.css:966](../../styles.css#L966).

### `tools/doc-coverage.js`: что считается именем

```
node tools/doc-coverage.js --all
node tools/doc-coverage.js docs/reference/build.md assets/build-media.js …
```

`PAGES` — карта «страница → файлы, которые она описывает». `namesOf(src)` выписывает из
файла имена, `check(page, srcs)` ищет каждое в тексте страницы.

Что `namesOf()` считает именем:

| файл | имя |
|---|---|
| `.css` | каждое `--имя:` (объявление пользовательского свойства) и каждое `@keyframes имя` |
| `.html` | то же, что в JS, но только внутри встроенных `<script>` без `src=`; остальные строки заменяются пустыми, номера строк сохраняются |
| JS | `function имя(` на любой глубине; `const/let/var имя = function`, `= (…) =>`, `= x =>` на любой глубине; `имя: function` (методы объектов) на любой глубине; любые `const/let/var` на уровне файла или IIFE |

Уровень файла определяется по отступу. Скрипт берёт минимальный отступ среди строк,
начинающихся с `const/let/var`:

```
минимальный отступ 0   → Node-скрипт: считаются переменные только на колонке 0
минимальный отступ N>0 → классический скрипт браузера (весь файл с отступом 4,
                         тела IIFE — 8): считаются переменные с отступом ≤ N + 4
```

В объявлении через запятую берётся каждое имя (запятые внутри скобок не делят), в
деструктуризации `{ a, b: c, d = 1 }` / `[p, q]` — имена после `:` и до `=`.

Исключения — `SKIP`: 24 однобуквенных имени и 15 частых коротких (`self`, `that`, `res`,
`req`, `err`, `ok`, `out`, `tmp`, `el`, `fn`, `cb`, `len`, `key`, `val`, `idx`).

«Упомянуто» значит: имя встречается в странице как отдельное слово — перед ним не буква,
цифра, `_`, `$` или `-`, после — не буква, цифра, `_` или `$`. С учётом регистра, в любом
месте страницы.

Вывод одной страницы:

```
names: 61, documented: 0, missing: 61
assets/build-media.js:30  fs
assets/build-media.js:31  path
…
```

Вывод `--all` — по строке на страницу, `✓` или `✗`, «описано/всего», под `✗` —
пропуски с отступом 4:

```
✗ docs/reference/deck.md — 0/124
    index.html:…  …
✓ docs/reference/build.md — 61/61
```

Коды выхода: `0` — пропусков нет, `1` — есть хотя бы один, `2` — неверные аргументы
(меньше двух и не `--all`), печатается подсказка.

## Почему так, а не иначе

**Веб-копии собираются скриптом заранее, а не в браузере и не руками.**
Перекодировать в браузере бессмысленно: телефон жюри сначала скачал бы тяжёлый
оригинал, а экономить нужно именно скачивание. Сервер тоже не перекодирует: страница
должна работать с `file://`, с флешки и со статического хостинга, где `serve.js` нет.
Сделать копии руками один раз — тоже не вариант: мастеры меняются (студия, новые дубли),
а у ручной копии параметры нигде не записаны. Скрипт держит параметры в коде, сравнивает
`mtime` и пересобирает только изменённое. Оригиналы не трогаются: шапка файла и
[voice/README.md](../../voice/README.md) называют `masters/` набором для «скачать
исходную» и для обучения RVC, его нельзя портить пережатием.

**64 кбит/с моно.** По шапке файла: питч открывают по QR через мобильный интернет
Таджикистана, и каждый мегабайт — это секунды, пока судья смотрит в пустой экран. Голос
ElevenLabs — моно 44,1 кГц; на 64 кбит/с отличия от оригинала уже не слышно, а размер
падает вдвое. Стерео или 128 кбит/с удвоили бы трафик без пользы для речи.

**Реплики дека — base64 в скрипте, а не 16 отдельных mp3.** Причина — в комментарии
[build-media.js:65](../../assets/build-media.js#L65): реплики дека идут через граф
«сломанного радио» на Web Audio. С `file://` отдельный файл для Web Audio — ресурс
чужого происхождения, и граф выдаёт тишину (то же ограничение Chrome описано в шапке
[15-voice-media.js:17](../../js/core/15-voice-media.js#L17)). У `data:`-адреса такой
проблемы нет. Цена — base64 тяжелее на треть; gzip на сервере возвращает почти всё
(1,74 МБ → 1,30 МБ).

**Пакет не в `index.html`.** Тот же комментарий: скрипт вставляется в фоне, когда меню
уже работает, чтобы 1,3 МБ звука не задерживали первый клик. Цена ошибки записана в
[09-alice-stream.js:151](../../js/presentation/09-alice-stream.js#L151): как
`defer`-скрипт пакет держал всю цепочку, и на канале 1 Мбит/с ни одна кнопка не работала
около семнадцати секунд.

**`window.ALICE_AUDIO = …`, а не `const ALICE_AUDIO`.** Шапка сгенерированного файла:
присваивание вместо объявления, чтобы повторная вставка не упала на повторном объявлении.
`loadAliceAudio()` после ошибки сети через 8 с вставляет скрипт заново, так что повтор
возможен.

**`aliceAudioArrived()` вызывает сам пакет.** У `async`-скрипта нет порядка, поэтому пакет
сам сообщает, что пришёл. Проверка `typeof … === "function"` нужна там, где функции нет:
в студии (`vm` в `voice/lib.js`) и при открытии файла отдельно.

**Несколько качеств видео.** Шапка `17-evidence.js`: оригинал весит 73 МБ, школьный канал
в Душанбе его не вытянет. 360p (~0,45 Мбит/с) проходит по слабому мобильному каналу,
540p (~1 Мбит/с) — по среднему, оригинал — когда страница открыта локально и качать
нечего. Один «средний» вариант проигрывал бы с обеих сторон: тормозил бы на телефоне и
мылил на ноутбуке ведущего. `+faststart` — чтобы воспроизведение начиналось после
индекса, а не после всего файла; `-maxrate` — чтобы CRF не давал пиков выше канала.
Буфер в 2× потолка — по коду; причина в комментариях не записана, вероятно, обычный
компромисс между ровным потоком и качеством сложных сцен.

**30 к/с вместо 60.** На записи урока люди сидят за партами, 60 к/с ничего не добавляют, а
половина кадров при том же CRF — заметная экономия. Причина выведена, в коде не записана.

**Логотип — сгенерированный SVG, а не растр и не canvas.** Из комментариев
[build-brand.js:1](../../assets/build-brand.js#L1) и [index.html:92](../../index.html#L92):

- это настоящая студийная трассировка, а не перерисовка. SVG сохраняет её точно на любом
  масштабе и плотности экрана; растр пришлось бы держать в нескольких размерах;
- анимация живёт внутри SVG. CSS в SVG, вставленном через `<img>`, выполняется, поэтому
  кристаллы плывут без единой строки скрипта на странице. Canvas потребовал бы цикл кадров
  на JS; анимированный растр (GIF, видео) тяжелее и не умеет `prefers-reduced-motion`;
- файлы подключены как внешние `<img>`, а не встроены в `index.html`: одна надпись — 145
  под-контуров, два встроенных файла добавили бы в разметку около 120 КБ трассы. Обратная
  сторона — правила `styles.css` внутрь `<img>` не достают
  ([styles.css:960](../../styles.css#L960)), поэтому вся анимация — в самом SVG.

**Знак разбит на области.** Шапка `build-brand.js`: пять кристаллов в исходнике
переплетены и приходят одной кашей под-контуров. Группировка по областям позволяет
осколкам плыть отдельно от шпиля, а не сдвигать весь знак блоком. Кластеризация по
пересечению рамок склеивает кластер, поэтому пороги в `region()` подобраны руками по
отладочной раскраске.

**Ключевые кадры генерируются из таблицы.** Комментарий
[build-brand.js:127](../../assets/build-brand.js#L127): каждый набор нужен дважды —
полный и ослабленный для `prefers-reduced-motion`. Масштабировать один набор через
CSS-переменную было бы короче, но `var()` внутри `calc()` в ключевом кадре движок
отбрасывает, и весь знак молча замирает.

**`GAIN` отдельно от таблицы.** Комментарий [build-brand.js:210](../../assets/build-brand.js#L210):
знак выводится шириной 78 px на `viewBox` шириной 240, одна единица SVG ≈ треть пикселя.
Расстояния из таблицы, разумные как числа, дают на экране около пикселя и читаются как
статичная картинка. Усиление умножает только сдвиг. Пыли нужно больше всех (2,4): именно
её глаз читает как парение. Таблица остаётся читаемой, движение настраивается в одном месте.

**Ослабление вместо остановки при `prefers-reduced-motion`.** Комментарий в `STYLE`
([build-brand.js:256](../../assets/build-brand.js#L256)): логотип, замерший посреди
движения, выглядит как сломанный файл, а настройка существует против больших размашистых
перемещений. Комментарий говорит «примерно до трети», код ослабляет до половины
(`REDUCED_AMP = 0.5`) — см. «Подводные камни».

**Проверка полноты — скрипт по именам, а не ручной список.** Шапка `doc-coverage.js`:
скрипт ловит только забытое целиком. Отличить описание от упоминания он не может и не
пытается — это работа ревьюера. Разбор идёт регулярными выражениями, без парсера JS: в
проекте нет npm-зависимостей, а договорённость об отступах (браузерный файл с отступом 4,
тело IIFE — 8, Node-скрипты с колонки 0) позволяет отличить уровень модуля от локальных
переменных по одному отступу.

## Связи

Все три скрипта — отдельные программы Node, общей области видимости браузерных скриптов
у них нет. Связи идут через файлы.

**`build-media.js`**

| читает | пишет | кто пользуется результатом |
|---|---|---|
| `assets/audio/<lang>/masters/*` (кроме `deck.*`) | `assets/audio/<lang>/<id>.mp3` | `VoiceMedia` (`sources()`) в `15-voice-media.js`; `audioFor()` в `voice/cues.js` (разметка субтитров) |

| `assets/video/*.mp4` | `*.540.mp4`, `*.360.mp4`, `*.poster.jpg` | `Evidence` в `17-evidence.js` (`VARIANTS`, атрибут `poster`) |

Внешняя программа — `ffmpeg` из `PATH`. Мастеры пишет студия (`serve.js`) или человек
руками; `masterFile()` в `voice/lib.js` и `15-voice-media.js` читают их напрямую как
запасной вариант.

**`build-brand.js`**

| читает | пишет | кто пользуется |

отмечает: знак теперь статическая разметка, скрипту подключать нечего.

и в корневом `README.md` («Файлы»).

## Функции

### `build-media.js`

#### `stale(src, out)` → `boolean`
`true`, если `out` надо пересобрать: стоит `FORCE`, `out` нет или `out.mtimeMs <
src.mtimeMs`. Только время изменения, без хешей. Вызывается для каждой веб-копии,
варианта видео и постера. Пакет `08b` проверяется своим условием (по самому новому из 16
мастеров), не через `stale()`.

#### `ff(args)` → `undefined`
`execFileSync("ffmpeg", ["-v", "error", "-y", …args], { stdio: "inherit" })`. Ошибки
`ffmpeg` идут прямо в консоль; ненулевой код выхода бросает исключение, и скрипт
останавливается — перехвата нет. Без `ffmpeg` в `PATH` — `ENOENT` на первой нужной сборке.
Пакет `08b` вызывает `execFileSync` напрямую, потому что ему нужен stdout, а не файл.

#### `kb(f)` → `string`
Размер файла в КБ, округлённый и выровненный до 6 знаков, с суффиксом « КБ». Только для
строк отчёта.

Внутри сортировки `ids` есть ключ-стрелка `k(s)`: `"0" + s` для `deck.slide*`, иначе
`"1" + s`. Сравнение никогда не возвращает 0 — имена файлов не повторяются.

### `build-brand.js`

#### `subpaths(d)` → `string[]`
Режет строку `d` перед каждой заглавной `M`, обрезает пробелы, выбрасывает пустые куски.
Относительную `m` в середине пути не учитывает (в исходнике её нет).

#### `bbox(d)` → `{ minx, miny, maxx, maxy }`
Рамка под-контура. Разбивает `d` на команды `M m Z z C c L l` и числа, ведёт перо
(`x`, `y`) и текущую команду (`c`). Для кривых в рамку входят и контрольные точки, так
что рамка может быть шире самой кривой — для раскладки по областям этого достаточно.
`Z` перо не двигает. Остальные команды SVG (`H V S Q T A`) не распознаются: их числа
съест предыдущая команда, и рамка выйдет неверной. Начальные значения — ±1e9.

#### `hit(p, q)` → `undefined`
Вложенная в `bbox()`: расширяет рамку точкой `(p, q)`.

#### `cx(it)`, `cy(it)` → `number`
Центр рамки по x и по y.

#### `region(it)` → `"word" | "kite" | "chipR" | "chipL" | "base" | "spire"`
Относит под-контур к области по порогам из таблицы в «Как это работает». Пороги —
координаты исходника 572×406; после перерисовки логотипа их надо проверять заново.

#### `emit(it)` → `string`
`<path fill="…" fill-opacity="…" d="…"/>`; `fill-opacity` пропускается, если равен `"1"`.

#### `num(n)` → `string`
Число с не более чем тремя знаками после запятой, без хвостовых нулей: `3.400` → `"3.4"`.

#### `frameCss(f, amp, gain)` → `string`
Один ключевой кадр в CSS: `opacity` без изменений, `transform` из
`translate(tx·amp·gain px, ty·amp·gain px) rotate(r·amp deg) scale(1 + (s − 1)·amp)` —
только те части, что есть в кадре, в этом порядке. Отступ 6 пробелов.

#### `keyframeSet(amp, sfx)` → `string`
Все 9 наборов `KEYFRAMES` как `@keyframes <имя><sfx> { … }` с амплитудой `amp` и
усилением из `GAIN` (по умолчанию 1). Зовётся дважды: `(1, "")` и `(REDUCED_AMP, "-r")`.

#### `bindings(sfx, indent)` → `string`
21 правило `селектор { animation: <набор><sfx> <длит>s ease-in-out infinite <задержка>s[ reverse]; }`
из `BINDINGS`. Зовётся дважды: с `""` на верхнем уровне и с `"-r"` внутри
`@media (prefers-reduced-motion: reduce)`.

### `tools/doc-coverage.js`

#### `namesOf(src)` → `Map<имя, номер строки>`
Читает файл, убирает `\r`, применяет правила из таблицы «что считается именем».
Для `.css` возвращается сразу после CSS-правил. Для `.html` сначала заменяет пустыми
строками всё, что не внутри встроенного `<script>`. Затем считает базовый отступ
объявлений и проходит по строкам четырьмя регулярными выражениями. Для каждого имени
запоминается первая строка.

#### `add(n, line)` → `undefined`
Вложенная в `namesOf()`: кладёт имя в карту, если оно непустое, не в `SKIP` и ещё не
встречалось.

#### `check(page, srcs)` → `{ total, missing }`
Читает страницу (нет файла — пустая строка, тогда пропущено всё), для каждого имени из
каждого исходника строит регулярное выражение «отдельное слово» и собирает пропуски
строками `<исходник>:<строка>  <имя>`. `total` — сумма имён по всем исходникам; имя,
встреченное в двух файлах, считается дважды.

Код верхнего уровня после `check()` разбирает `args`: `--all` — цикл по `PAGES`;
два и больше аргументов — одна страница и её исходники; иначе подсказка и выход с
кодом 2. В конце — `process.exit(failed ? 1 : 0)`.

## DOM, классы, события, хранилище

Скрипты в браузере не выполняются: DOM, `localStorage` и слушателей у них нет. Всё, что
они оставляют странице, — в файлах.

**Пакет `08b`** объявляет `window.ALICE_AUDIO` (объект `id → base64 mp3`, 16 ключей:
`deck.slide01`…`deck.slide05`, `deck.bg01`…`deck.bg11`) и зовёт глобальную
`aliceAudioArrived()` из `09-alice-stream.js`, если она есть. Ключи совпадают с
`voiceId`, которые `09-alice-stream.js` назначает строкам реплик.

**Видео**: имена `<base>.540.mp4`, `<base>.360.mp4`, `<base>.poster.jpg` зашиты в
`Evidence` (`BASE = "assets/video/classroom_trial"`). Переименование файла без правки
`17-evidence.js` ломает плеер.

**Классы внутри `brand-mark.svg`**: `.cr` и `.cr-spire`, `.cr-base`, `.cr-chipL`,
`.cr-kite`, `.cr-chipR` (кристаллы); `.dust-chips` → `.chip .chip-1`…`.chip-7`;
`.dust-dots` → `.spk .spk-1`…`.spk-6`; `.dust-stars` → `.star .star-1`…`.star-3`.
Ключевые кадры: `cc-breathe`, `cc-drift-a/b/c`, `cc-float-a/b/c`, `cc-twinkle`, `cc-star`
и их копии с суффиксом `-r`. Медиа-запрос `prefers-reduced-motion: reduce`. В
`brand-wordmark.svg` — один класс `.wordmark`, без стиля. Эти классы живут в отдельном
документе картинки: `styles.css` их не видит, а правила `.boot-brand …` страницы не
попадают внутрь SVG.

**Консоль**: `build-media.js` печатает строку на каждый собранный файл (`audio`, `bundle`,
`video`, `poster` + путь + размеры) и итог; `build-brand.js` — число под-контуров по
областям и размеры двух файлов; `doc-coverage.js` — отчёт и код выхода 0/1/2.

## Подводные камни

**`build-media.js`**

1. **Свежесть — только по `mtime`.** Мастер, восстановленный из архива или скопированный
   с сохранением времени, может оказаться «старше» копии — и не пересоберётся. После
   такой замены — `--force`.
2. **Удаление реплики не пересобирает пакет.** Условие сравнивает пакет с самым новым из
   оставшихся мастеров; удалённый `deck.*.mp3` не делает пакет устаревшим, и реплика
   остаётся в `08b` до `--force`. Если удалить все `deck.*.mp3`, пакет не трогается вовсе.
3. **`deck.*` не в mp3 теряется молча.** Проход 1 исключает всё, что начинается с
   `deck.`, проход 2 берёт только `.mp3`. `deck.slide06.wav` не попадёт никуда.
4. **Два мастера с одним именем и разными расширениями** (`x.wav`, `x.mp3`) пишут одну
   копию `x.mp3`; что победит, зависит от порядка `readdir` и времён.
5. **Пакет — только русский.** `DECK_MASTERS` зашит на `ru`. Реплики дека на других
   языках приходят из записей студии (`VOICE_CLIPS`), не отсюда.
6. **Падение посреди прогона.** Ошибка `ffmpeg` бросает исключение и останавливает
   скрипт; собранное до этого остаётся, следующий запуск продолжит с недостающего.
   Пакет пишется одним `writeFileSync` после перекодирования всех 16 реплик, так что
   наполовину записанным он не бывает (кроме сбоя самой записи).
7. **Любой `*.mp4` в `assets/video/` — источник.** Положенный туда посторонний ролик
   получит свои варианты и постер. Плеер знает только `classroom_trial`.
8. **«Без тегов» — не совсем.** `-map_metadata -1` не переносит теги исходника, но
   `ffmpeg` всё равно пишет короткий ID3v2.4 с полем `TSSE` = `Lavf…` (около 44 байт):
   base64 каждой реплики в `08b` начинается с `SUQzBA` («ID3\x04»). Вреда нет.
9. **«Первые несколько килобайт» — на деле около 190 КБ.** Индекс `moov` у 175-секундного
   ролика весит 186–197 КБ во всех трёх файлах. На канале 0,45 Мбит/с это ~3,4 с до
   первого кадра. Постер на это время закрывает пустоту.
10. **Сгенерированный `08b` не правят руками** — следующий запуск его перезапишет.
    Текст реплик живёт в `08-alice-lines.js`, звук — в мастерах.

**`build-brand.js`**

11. **Разбор держится на формате экспорта.** Регулярное выражение требует атрибуты
    `<path>` строго в порядке `fill`, `fill-opacity`, `d`, без других между ними. Путь с
    другим порядком или лишним атрибутом пропускается молча; исключение — только если не
    нашлось ни одного. После перерисовки исходника сверьте отчёт в консоли: сейчас
    69 / 19 / 9 / 15 / 16 / 145 под-контуров.
12. **`bbox()` знает только `M m C c L l Z z`** и числа вида `-12.5`. Команды `H V S Q T A`,
    экспонента (`1e-5`) или слитые числа (`.5.3`) дадут неверные рамки и неверные области.
13. **Проверка `isFinite(bb.minx)` ничего не отсеивает.** Начальные значения рамки — ±1e9,
    это конечные числа. Под-контур без координат получил бы `minx = 1e9`, ушёл бы в `word`
    (`miny >= 278`) и растянул `viewBox` надписи до миллиарда. С текущим исходником не
    срабатывает: каждый под-контур начинается с `M`.
14. **Правило заливки потеряно.** У исходника на корне `fill-rule:evenodd`, у результатов
    правила нет (по умолчанию `nonzero`), а пути разрезаны на под-контуры. Внутренний
    под-контур, который в исходнике вырезал отверстие, теперь закрашивается отдельно. В
    исходнике у 49 из 74 путей больше одного под-контура, и в 4 парах один вложен в другой
    по рамке — кандидаты в такие отверстия. Файлы в проекте собраны этим же кодом, так что
    это уже видимая картина; глазами разница не проверялась.
15. **Две группы у осколка и звезды — не склеивать.** Внешняя ставит позицию атрибутом
    `transform`, внутренняя анимирует CSS-свойство `transform`. В одной группе CSS заменил
    бы атрибут, и всё уехало бы в точку (0, 0).
16. **Без CSS-анимации пыль не видна** (`opacity: 0` у `.chip`, `.spk`, `.star`), кристаллы
    остаются. Это и есть запасной вид.
17. **Пыль частично уходит за `viewBox`.** Осколок `chip-7` стоит на y = 8 и всплывает
    на ~20 ед. (с учётом `GAIN`, в повёрнутых на 34° координатах — около 17 ед. по
    вертикали), то есть выше y = 0. Осколок `chip-3` на x = 382 смещается вправо до
    ~14 ед. при правой границе 390. Сдвиг анимации идёт в системе координат внешней
    группы, то есть повёрнутой. `style="overflow:visible"` на корне, вероятно, помогает
    только при встраивании SVG в разметку: `<img>` обрезает картинку по своему
    прямоугольнику.
18. **`var()` в ключевых кадрах не использовать** — комментарий
    [build-brand.js:130](../../assets/build-brand.js#L130): знак замрёт целиком.
19. **Скрипт перезаписывает оба файла при каждом запуске**, проверки свежести нет. При
    неизменном исходнике результат побайтно тот же.

**`tools/doc-coverage.js`**

20. **Упоминание засчитывается как описание** — в любом месте страницы, даже в этом
    разделе. Полноту описаний проверяет только чтение.
21. **Уровень модуля определяется по отступу.** В браузерном файле (база 4) локальные
    переменные функций верхнего уровня (отступ 8) неотличимы от переменных IIFE и тоже
    требуются. В Node-скрипте (база 0) не проверяется ничего глубже колонки 0 — `ids`,
    `newest`, `masters` в `build-media.js` скрипт не видит. Одна строка `const` с колонки 0
    в браузерном файле (например, внутри шаблонной строки) сбросит базу в 0, и переменные
    IIFE перестанут проверяться.
22. **Что не распознаётся как функция:** методы в сокращённой записи `name() {}`,
    стрелки в объекте `name: () =>`, присваивания `obj.name = function`, `window.name = …`,
    методы классов. Их надо описывать без подсказки скрипта.
23. **`.html`:** однострочный `<script>…</script>` пропускается целиком — открывающий и
    закрывающий тег на одной строке не включают режим скрипта.
24. **Граница слова несимметрична.** Перед именем не допускается `-`, после — допускается.
    Поэтому `--accent` засчитывается упоминанием `--accent-2`, а JS-имя, стоящее только
    внутри `cc-имя`, не засчитывается.
25. **Новый исходник — в `PAGES`**, иначе `--all` его не проверит. Ручной вызов с явным
    списком файлов работает и без карты.
