# Сервер — справочник

> Файлы: `serve.js` (996 строк), `tools/qr.js` (227 строк), `start.bat` (27 строк) · Место в порядке загрузки: вне страницы — процесс Node, который отдаёт её и все `/api/*`
> Связанные страницы: [voice.md](voice.md) (студия, манифест, субтитры — то, что `serve.js` зовёт из `voice/*`), [audio.md](audio.md) (`19-neural-voice.js` — клиент `/api/tts`), [sandbox.md](sandbox.md) (`20-ai-sandbox.js` — клиент `/api/ollama/*`), [README.md](README.md), [../ARCHITECTURE.md](../ARCHITECTURE.md)

## Коротко

`serve.js` — единственный сервер проекта: Node без зависимостей, один процесс. Отдаёт презентацию как статику (gzip, ETag/304, диапазоны байтов) на `:8779`, дополнительно на `:80`, если порт свободен, и по HTTPS на `:443` (запасной `:8443`) с сертификатом `*.local-ip.sh`. Поверх статики — API студии озвучки (только с этой машины), мост к локальной Ollama с очередью, где ведущий всегда впереди гостей, и `/api/tts` — голос Элис без записи по цепочке ElevenLabs → Piper → 503. Телефоны жюри приходят по QR: ссылку сервер печатает в консоли псевдографикой и показывает на весь экран на `/qr`; QR-код рисует `tools/qr.js`, самописный кодировщик ISO/IEC 18004. Запускается двойным щелчком по `start.bat`, который проверяет Node и вызывает `node serve.js 8779 --open`.

Ведущий видит окно консоли со ссылками, QR и состоянием голоса; жюри видит презентацию на телефоне и в полигоне — своё место в очереди к модели.

## Как это работает

### Запуск и командная строка

```
start.bat [порт]                        → node tools\get-piper.js
                                        → node serve.js <порт|8779> --open --no-piper-download
node serve.js [порт] [--open] [--no-guests] [--no-https] [--nip] [--no-piper-download]
```

|---|---|---|
| первое число в аргументах | порт HTTP (`PORT`) | [serve.js:68](../../serve.js#L68) |
| `PORT` (env) | порт, если числа в аргументах нет; `start.bat` ставит и то, и другое | там же |

Последовательность старта ([serve.js:957](../../serve.js#L957)):

1. Загрузка модуля: `require` зависимостей из `voice/` и `tools/qr.js`, `HAS_FFMPEG = cues.hasFfmpeg()` (синхронный запуск `ffmpeg -version`), регистрация маршрутов `route(...)`, вычисление `OLLAMA` и `PIPER` (`piperCheck()`; если Piper нет, `PIPER_FETCH` решает, качать ли его после старта).
2. `server.listen(PORT, "0.0.0.0")`. Порт занят → обработчик `error` печатает «уже запущен», по `--open` открывает `http://localhost:PORT/` и выходит с кодом 0 через 300 мс.
3. `lib.writeManifest()` — пересборка `js/core/00-voice-clips.js` без смены режима (файлы могли подложить руками).
4. `listen80()` — второй HTTP-сервер на `:80` с тем же обработчиком; не вышло — ссылка несёт `:8779`.
5. Если `USE_HTTPS`: `ensureTls()` (сертификат с диска или скачать), `listenHttps()` (`:443`, иначе `:8443`). Успех → `JURY.tls`, `JURY.httpsPort`.
6. `juryLinks()` — ссылки для всех сетей ноутбука, первая — главная (`JURY.url`).
7. Баннер в консоль (см. «Консоль при старте»), QR главной ссылки через `qr.toConsole(qr.encode(JURY.url))`.
8. По `--open` — `openBrowser(local)`.

### Уровни доступа

Сервер слушает все интерфейсы (`0.0.0.0`), поэтому каждый запрос классифицируется по адресу отправителя `req.socket.remoteAddress` (префикс `::ffff:` срезается):

| Кто | Проверка | Что можно |
|---|---|---|
| эта машина | `isLocal(req)`: `127.0.0.1`, `::1` или любой адрес из `os.networkInterfaces()` этой машины | всё: студия, запись файлов, полигон и голос без очереди и лимитов |
| гость | `isLan(req)`: `10.*`, `192.168.*`, `172.16–31.*`, `169.254.*`, `127.*`, IPv6 `fc*`/`fd*`/`fe80*` | статика; маршруты с `{ guests: true }` — если сервер запущен без `--no-guests` |
| остальные | — | статика и маршруты без флагов (`/api/voice/info`, `/api/voice/manifest`, `/api/lan`) |

`127.x`, кроме `127.0.0.1`, не входит в `isLocal` (интерфейс loopback перечисляет только `.1`), но входит в `isLan`. Отправить пакет с такого адреса может только эта же машина, и, по комментарию в коде, тесты пользуются этим, чтобы выглядеть гостем. Самих тестов в репозитории нет.

Свой LAN-адрес — тоже «эта машина»: презентация, открытая на ноутбуке по `https://192-168-1-5.local-ip.sh/`, приходит на сервер с `192.168.1.5`, а не с `127.0.0.1`, и без этой ветки ведущий стал бы гостем у себя же.

Флаги маршрута ([serve.js:224](../../serve.js#L224)): `{ local: true }` — только эта машина, иначе 403 «студия работает только на компьютере, где запущен сервер»; `{ guests: true }` — эта машина или гость при `GUESTS`, иначе 403 «полигон и голос открыты только для устройств в этой Wi-Fi сети»; `{}` — без проверки. Вне маршрутов: `/studio.html` с чужого адреса — 403 текстом, `/tools/*` — 404 всем.

### Разбор запроса

```
http.createServer(handler)                       тот же handler у :80 и у HTTPS
 │  u = new URL(req.url, "http://localhost")
 ├─ /api/tts*      → corsFor(req) → заголовки CORS; OPTIONS → 204 (только эта машина) или 403
 ├─ /api/*         → handleApi(): первый маршрут с тем же методом и совпавшей регуляркой
 │                    → проверка local/guests → r.fn(req, res, m, q); исключение → JSON {ok:false, why}
 │                    → ничего не совпало → 404 {ok:false, why:"нет такого адреса"}
 ├─ /qr            → sendQrPage(res)
 ├─ /tools/*       → 404 (Piper, кеш голоса, сертификат — не для страницы)
 ├─ /studio.html   → 403, если не эта машина
 ├─ не GET/HEAD    → 405
 └─ иначе          → serveStatic()
```

Ошибки из обработчиков маршрутов — объекты `lib.fail(status, why)` (`Error` с полем `status`). `handleApi` отвечает `{ ok: false, why }` с этим статусом; без статуса — 500. Ошибки 5xx пишутся в консоль строкой «ошибка: …».

### Статика

`serveStatic(req, res, pathname)` ([serve.js:153](../../serve.js#L153)):

1. `decodeURIComponent` (битый `%` → 400), `/` в конце → `index.html`.
2. `path.resolve(ROOT, "." + rel)`; результат вне `ROOT` → 403. Любой сегмент пути, начинающийся с точки, → 404 (скрытые файлы и служебная папка настроек инструментов в корне проекта).
3. `fs.stat`: нет файла или это каталог → 404. Тип — по расширению из `MIME`, иначе `application/octet-stream`.
4. ETag слабый: `W/"<размер base36>-<mtime в мс base36>"`. Совпал с `If-None-Match` → 304 с `Cache-Control: no-cache`.
5. Сжатие: тип подходит под `COMPRESSIBLE` (`text/*`, `application/json`, `image/svg+xml`), файл больше 1024 байт, клиент шлёт `gzip` в `Accept-Encoding` → `zlib.gzipSync(…, { level: 9 })`, результат кладётся в `GZ_CACHE` по ключу `путь|mtimeMs|размер`, ответ 200 с `Content-Encoding: gzip`, `Vary: Accept-Encoding`. Диапазоны для сжатого ответа не поддерживаются — это только текст.
6. Остальное — потоком `fs.createReadStream` с `Accept-Ranges: bytes`. Заголовок `Range` вида `bytes=a-b`, `bytes=a-` или `bytes=-n` (один диапазон) → 206 с `Content-Range`; начало за концом → 416 `bytes */<размер>`. Несколько диапазонов через запятую регулярка не принимает → обычный 200.
7. `HEAD` получает те же заголовки без тела.

Все статические ответы — `Cache-Control: no-cache`, все ответы API — `no-store` (через `send()`).

Для коротких реплик `retime` возвращает `null`.

### Очередь к Ollama

Состояние: `GEN = { busy, waiting, lastModel }`, `GUEST_QUEUE = 6`, `guestBusy` (IP гостей с запросом в работе). Генерация — строго одна за раз.

Обработчик `POST /api/ollama/generate` ([serve.js:384](../../serve.js#L384)):

1. Тело читается (`readBody`, 256 КБ для этой машины, 64 КБ для гостя) и разбирается как JSON.
2. Эта машина: `GEN.lastModel = ask.model` — модель ведущего запоминается.
3. Гость, по порядку:
   - прогрев (`stream === false` и `options.num_predict <= 1` — так `20-ai-sandbox.js` грузит модель при открытии полигона) → сразу 200 `{ model, response: "", done: true }`, без Ollama: модель греет ноутбук ведущего;
   - с этого IP уже идёт запрос (`guestBusy`) → 429 «с этого телефона уже идёт запрос»;
   - гостей в `GEN.waiting` уже `GUEST_QUEUE` → 503 «очередь ядра заполнена»;
   - `ask.model = GEN.lastModel` (если ведущий уже что-то спрашивал), `options.num_predict = min(num_predict || 160, 200)`; тело пересобирается; IP — в `guestBusy`.
4. Создаётся задание `job = { local, tell(n), start(done) }`.
5. Постановка: задание ведущего вставляется перед первым гостем в `GEN.waiting` (после других заданий ведущего), гость — в конец. Идущую генерацию никто не прерывает.
6. Если `GEN.busy` — клиенту сразу уходит `{"queued":<место>}` и потом каждые 2,5 с (`setInterval`). Первая такая строка отправляет заголовки 200 `application/x-ndjson`.
7. `nextGen()`: если свободно, снимает первое задание, ставит `busy`, сообщает всем оставшимся новые места и зовёт `job.start(done)`.
8. `start`: останавливает таймер очереди; клиент уже ушёл → сразу `done()`. Иначе `POST /api/generate` в Ollama; ответ передаётся `pipe(res, { end: false })`, по `end` дописывается `\n` (тело ошибки Ollama может прийти без перевода строки, а страница читает построчно) и вызывается `finish()`. Ошибка соединения: заголовков ещё не было → 502 JSON; были → строка `{"error": "..."}`. Таймаут сокета — 300 с.
9. `finish()` вызывает `done` ровно один раз (флаг `ended`) → `busy = false` → `nextGen()`.
10. Закрытие ответа (`res` `close`: ответ закончен или клиент ушёл): `gone = true`, таймер снят, IP гостя убран из `guestBusy`, задание убрано из очереди, остальным пересчитаны места. Если генерация шла — `up.destroy()` обрывает запрос к Ollama, и она перестаёт генерировать.

```
           ведущий ─┐
                    ▼ (перед первым гостем)
 GEN.waiting: [ в1, в2, г1, г2, г3 … ≤6 гостей ]  ──nextGen()──►  Ollama (одна генерация)
                 │                                                    │
                 └── {"queued":n} каждые 2,5 с                        └── поток NDJSON как есть
```

Страница (`20-ai-sandbox.js`) на строке `queued` переводит таймер первого слова на длинный (`COLD_MS`) и показывает место в очереди.

`GET /api/ollama/(version|tags|ps)` идёт мимо очереди: `ollama(res, method, apiPath, body)` проксирует запрос, `pipe` ответа, 502 при ошибке, обрыв запроса к Ollama при уходе клиента.

### Голос без записи (`/api/tts`)

Цепочка в `speakFor(req, res, guest)` ([serve.js:652](../../serve.js#L652)):

```
POST /api/tts {text, mood, lang, engine}
 ├─ гость и с этого IP уже ждут голос (ttsBusy) → 429
 ├─ text: обрезка до 600 (гость) / 1200 символов, пусто → 400
 ├─ mood ∉ MOOD_TAGS → "neutral";  lang по умолчанию "ru";  engine: auto | elevenlabs | piper
 │
 ├─ engine ≠ piper и есть ключ:
 │    ключ кеша sha1("eleven"|voiceId|model|settings|outputFormat|mood|text)
 │    в кеше → ответ elevenlabs (бесплатно, даже в паузе и сверх лимита гостей)
 │    иначе, если гость не превысит лимит и (engine = elevenlabs или пауза кончилась):
 │         elevenSay() → в кеш → ответ elevenlabs;  гость: guestChars += длина
 │         ошибка → пауза 5 мин (401/403) или 1 мин (прочее), why = текст ошибки
 │    note = "ElevenLabs: <лимит для гостей исчерпан | why | пауза после ошибки>"
 ├─ ключа нет: note = "ElevenLabs: ключ не задан"
 │
 ├─ Piper нет или lang ≠ "ru" → 503 {ok:false, why: note[; Piper не найден]}
 └─ ключ кеша sha1("piper"|имя голоса|mood|text) → в кеше или piperSay() через ttsQueue
      → ответ piper, X-TTS-Note = note
```

Ответ — `sendAudio()`: `audio/mpeg` (ElevenLabs) или `audio/wav` (Piper), `X-TTS-Engine: elevenlabs|piper`, `X-TTS-Note` (почему не ElevenLabs, через `encodeURIComponent`). `19-neural-voice.js` читает оба заголовка, а для страниц с другого сервера `corsFor` делает их видимыми (`Access-Control-Expose-Headers`). Ошибка Piper (код выхода, таймаут) уходит в `handleApi` и становится 500 JSON.

**ElevenLabs.** Конфиг перечитывается на каждый запрос (`elevenConfig()`): файл `%USERPROFILE%\.terminal-shattered\elevenlabs.json` (`ELEVEN_FILE`, вне проекта) поверх `ELEVEN_DEFAULTS`. Поля, которые читает код: `apiKey`, `voiceId`, `voiceName`, `model`, `settings` (сливается с умолчаниями по полям), `outputFormat`, `guestBudget`. Переменные окружения сильнее файла (см. таблицу выше). Умолчания: голос `VD1if7jDVYtAKs4P0FIY` (Milly Maple — Cool and Bright, профессиональный клон), модель `eleven_v4`, `stability: 0.5`, `similarity_boost: 1.0`, `mp3_44100_128`; `language_code` не передаётся — язык определяется сам. `elevenSay(c, text, mood)` шлёт `POST https://api.elevenlabs.io/v1/text-to-speech/<voiceId>?output_format=<outputFormat>` с заголовком `xi-api-key`, телом `{ text, model_id, voice_settings }`; настроение — тег Eleven v4 в начале текста (`MOOD_TAGS`: `crit` → `[panicked, breathless]`, `loop` → `[disoriented, slow, distant]`, `ok` → `[sigh] [relieved, soft]`, `neutral` → без тега). Таймаут 20 с. Не 200 или пустое тело → ошибка с `detail.message`/`detail.status` из ответа и полем `status`.

**Лимит гостей.** `eleven.guestChars` — сколько символов новых фраз гости уже озвучили через ElevenLabs за этот запуск. Лимит `guestBudget(c)` — 3000 по умолчанию (около дюжины реакций). Фраза, которая перешла бы лимит, идёт в Piper; фразы из кеша бесплатны всем. Ведущего лимит не касается.

**Piper.** `PIPER` заполняет `piperCheck()` — при старте и ещё раз после фоновой загрузки. Пути берёт у `getPiper.paths()`: `tools/piper/piper/piper.exe` (или `piper` вне Windows) и по голосу на язык из `VOICES` — `tools/piper/voices/ru_RU-irina-medium.onnx` и `en_US-lessac-medium.onnx`; у каждого голоса частота — `audio.sample_rate` из соседнего `.onnx.json` (по умолчанию 22050). Голоса нет на диске — языка нет в `PIPER.voices`. `speakFor` берёт `PIPER.voices[lang]`; нет голоса (таджикский — его у Piper нет вовсе) — 503 с причиной «у Piper нет голоса для «tj»», страница переходит на синтез браузера. `piperSay(text, mood, v)` запускает `piper --model <голос> --output_raw --quiet` плюс четыре параметра настроения из `MOODS` (`--length_scale`, `--noise_scale`, `--noise_w`, `--sentence_silence`), рабочая папка — папка исполняемого файла, окно скрыто. В stdin — текст одной строкой (пробелы схлопнуты); из stdout — сырой PCM, который `wav(pcm, rate)` оборачивает в 44-байтный заголовок RIFF (PCM, моно, 16 бит). Процесс убивается через 30 с; ненулевой код или пустой вывод → ошибка с последними 300 символами stderr. Запуски выстроены в цепочку `ttsQueue`: Piper работает по одному.

**Загрузка Piper.** В репозитории Piper нет (`.gitignore`). Если при старте чего-то не хватает (`getPiper.present()` ложно: нет exe или одного из голосов), нет переопределений `PIPER_EXE`/`PIPER_VOICE*` и флага `--no-piper-download` (`PIPER_FETCH`), после баннера `fetchPiper()` зовёт `ensurePiper()` из [tools/get-piper.js](../../tools/get-piper.js) — в том же процессе, асинхронно: сервер уже отвечает. Ход загрузки пишется в окно по ~10 %, по окончании `piperCheck()` перечитывает файлы — новые голоса включаются без перезапуска. Не скачалось — причина в окне, повтор при следующем запуске. Так работает `node serve.js` без запускателя; `start.bat` и `start.sh` сначала запускают `node tools/get-piper.js` (проверка фразой, при нужде загрузка — до сервера, на виду) и передают серверу `--no-piper-download`.

`start.sh` — тот же запуск для macOS и Linux: проверяет `node`, запускает `node tools/get-piper.js` и делает `exec node serve.js <порт> --open --no-piper-download`. Почему так: Piper — ~160 МБ бинарников и двух моделей, для git это балласт, а у GitHub лимит 100 МБ на файл и мягкий — на репозиторий. Цена — первый запуск ждёт загрузку (пара минут); дальше проверка — по фразе на голос, около секунды. `node serve.js` без запускателя по-прежнему качает в фоне — чтобы слабый канал не задерживал сервер, запущенный руками. ### CORS для `/api/tts`

Страница, открытая с другого статического сервера на этой машине (`python -m http.server 8000`), ищет голос на `:8779` того же хоста (`19-neural-voice.js`, `bases()`). `corsFor(req)` разрешает это и только это: имя хоста из `Origin` должно совпасть с именем из `Host` (порт не важен), либо оба — loopback (`localhost`, `127.0.0.1`, `::1`, вложенная функция `loop`). Тогда — `Access-Control-Allow-Origin: <origin>`, `Vary: Origin`, `Access-Control-Expose-Headers: X-TTS-Engine, X-TTS-Note`. Предзапрос `OPTIONS` (его вызывает `Content-Type: application/json`) получает 204 с `Access-Control-Allow-Methods: GET, POST`, `Access-Control-Allow-Headers: Content-Type`, `Access-Control-Max-Age: 600` — только если CORS разрешён и запрос с этой машины; иначе 403. Сайт из интернета заголовков не получает и потратить кредиты ElevenLabs через этот сервер не может. Остальные `/api/*` CORS не отдают вовсе.

### Ссылка для телефонов жюри и HTTPS

**Адреса.** `lanAddresses()` перебирает `os.networkInterfaces()`: IPv4, не внутренний, из диапазонов `192.168.*`, `10.*`, `172.16–31.*`, имя адаптера не похоже на виртуальный (`tailscale`, `zerotier`, `vethernet`, `virtualbox`, `vmware`, `hyper-v`, `wsl`, `docker`, `vpn`, `loopback`, `bluetooth`). Адреса VPN вроде Tailscale (`100.*`) не проходят уже по диапазону. Порядок — порядок интерфейсов в ОС; первый адрес — главный.

**Ссылка для адреса** — `juryUrlFor(ip)`, считается на каждый запрос `/qr` и `/api/lan`, а не один раз при старте:

1. Есть сертификат и HTTPS-порт → имя `192-168-1-5.local-ip.sh` (точки → дефисы). `resolvesTo(host, ip)` проверяет, что DNS этой машины отвечает на имя этим же адресом (`dns.lookup`, таймаут 1,5 с); итог, и положительный, и отрицательный, кешируется в `DNS_SEEN` на 60 с. Совпало → `https://<имя>/` (порт в ссылке — только если это `8443`).
2. Иначе `juryLink(useNip, ip)`: с `--nip` и если `<ip>.nip.io` резолвится (`checkNip`) — `http://<ip>.nip.io/`, иначе голый `http://<ip>/`; `:8779` в ссылке, только если `:80` занять не удалось (`JURY.port80`).

`juryLinks()` собирает `{ name, ip, url }` по всем адресам и кладёт первую ссылку в `JURY.url`. Переключили ноутбук на точку доступа телефона (`172.20.10.x` у iPhone, `192.168.43.x` у Android) — следующий `/qr` уже с новым адресом: сертификат выписан на `*.local-ip.sh` и к адресу не привязан.

**Сертификат.** local-ip.sh — публичная DNS-зона: `192-168-1-5.local-ip.sh` отвечает `192.168.1.5`. Сервис публикует wildcard-сертификат Let's Encrypt на `*.local-ip.sh` вместе с закрытым ключом. `ensureTls()`:

1. Читает `tools/https/server.pem` и `server.key`, проверяет их `readTls()`: X509 разбирается (`crypto.X509Certificate`), в `subjectAltName` есть `DNS:*.local-ip.sh`, ключ подходит к сертификату (`checkPrivateKey`), срок `validTo` не истёк. Цепочку доверия код не проверяет — это делают браузеры телефонов.
2. До конца срока больше 14 дней → берётся он.
3. Иначе оба файла качаются параллельно (`fetchText(TLS_SRC + "server.pem")` и `"server.key"`, `TLS_SRC = https://local-ip.sh/`, таймаут 10 с, принимается только статус 200, редиректы не обрабатываются), проходят ту же проверку и записываются в `tools/https/`.
4. Скачанное не подошло или не скачалось — остаётся старый сертификат, если он ещё действует; нет и его — HTTPS не поднимается, ссылка `http`.

`listenHttps(tls)` берёт обработчик основного сервера (`server.listeners("request")[0]`) и через вложенную `tryPort(port)` пробует `https.createServer` на `:443`, потом на `:8443`; оба заняты → 0, HTTPS нет. Сертификат ставится, даже если имя пока не резолвится (нет интернета при старте): ссылка всё равно пересчитывается при каждом запросе.

### QR-кодировщик (`tools/qr.js`)

Стандарт ISO/IEC 18004 в минимальном объёме: байтовый режим, уровень коррекции M (восстанавливает около 15 % модулей), версии 1–10 (21×21 … 57×57 модулей, до 213 байт). По комментарию в файле, результат сверен модуль в модуль с Python-пакетом `qrcode` при той же версии и маске. Ссылка `https://192-168-1-5.local-ip.sh/` — 32 байта, самая длинная вида `https://192-168-100-200.local-ip.sh:8443/` — 41; обе влезают в версию 3 (29×29, 42 байта).

`encode(text, opts)`:

1. **Байты.** Текст → UTF-8 (`Buffer.from`).
2. **Версия.** Наименьшая `ver` из 1…10, для которой `dataCodewords(ver) ≥ длина + 2` (версии 1–9: 4 бита режима + 8 бит длины = 1,5 байта, округлено до 2) или `+ 3` для версии 10 (16 бит длины). Не влезло в 10 → исключение «QR: текст слишком длинный». `opts.version` задаёт версию явно (без проверки ёмкости).
3. **Ёмкость.** `rawModules(ver)` — число модулей под данные и коррекцию: `(16v + 128)·v + 64` минус выравнивающие узоры (`n = ⌊v/7⌋ + 2` позиций по оси → `(25n − 10)·n − 55` модулей) и минус 36 модулей информации о версии с 7-й версии. `⌊rawModules/8⌋` — всего кодовых слов; `dataCodewords(ver)` вычитает из них коррекцию `ECC_PER_BLOCK[ver] · NUM_BLOCKS[ver]`. Остаток `rawModules mod 8` — «лишние» биты, которые остаются светлыми и потом маскируются.
4. **Поток битов** (`codewords(bytes, ver)`, помощник `put(v, n)` пишет `n` старших битов): индикатор режима `0100` (байты), длина (8 бит, для версии 10 — 16), сами байты, терминатор до 4 нулей, нули до границы байта, затем байты-заполнители `0xEC`, `0x11` по очереди до ёмкости.
5. **Блоки и Рида–Соломон.** Кодовые слова делятся на `NUM_BLOCKS[ver]` блоков; если не делится нацело, первые `short` блоков на одно слово данных короче. Для каждого блока считается остаток деления на порождающий многочлен степени `ECC_PER_BLOCK[ver]`:
   - `gfMul(x, y)` — умножение в GF(256) по модулю `x⁸ + x⁴ + x³ + x² + 1` (`0x11D`), «крестьянским» сдвигом с редукцией;
   - `rsDivisor(degree)` — коэффициенты многочлена `∏(x − αⁱ)`, `i = 0…degree−1`, `α = 2`, старший единичный коэффициент опущен;
   - `rsRemainder(data, div)` — деление столбиком в форме сдвигового регистра: на каждый байт `factor = байт ⊕ r[0]`, сдвиг, `r[i] ⊕= div[i]·factor`. Остаток — байты коррекции.
   Короткому блоку после подсчёта коррекции дописывается заглушка `0`, чтобы все блоки были одной длины.
6. **Чередование.** Итоговая последовательность — по столбцам: i-е слово первого блока, i-е второго и так далее, сначала данные, потом коррекция; заглушки коротких блоков (индекс `shortLen − eccLen`) пропускаются.
7. **Матрица** (`build(ver, words, mask)`): размер `4·ver + 17`; два массива — `m` (тёмный/светлый) и `fn` (служебный модуль). Помощники `set(x, y, dark)` (ставит и помечает служебным) и `bit(v, i)`. По порядку:
   - синхрополосы — строка 6 и столбец 6, тёмные на чётных позициях;
   - три поисковых узора 7×7 с разделителями (`finder(cx, cy)`, квадрат 9×9 вокруг центров `(3,3)`, `(size−4, 3)`, `(3, size−4)`): тёмный, если чебышёвское расстояние от центра не 2 и не 4;
   - выравнивающие узоры 5×5 с версии 2: позиции `6, …, size−7` с шагом `⌈(4v + 4)/(2n − 2)⌉·2` (для версий 7–10: `6, 22, 38` … `6, 28, 50`), во всех сочетаниях, кроме трёх углов с поисковыми узорами; тёмный, если расстояние от центра не 1;
   - `format(0)` — резервирует места под информацию о формате;
   - с версии 7 — информация о версии: 6 бит номера + 12 бит BCH(18,6) с многочленом `0x1F25`, два блока 6×3 у правого верхнего и левого нижнего поисковых узоров;
   - данные: зигзаг столбцами по два справа налево, столбец 6 пропускается, направление (вверх/вниз) чередуется; биты слов от старшего, служебные модули обходятся;
   - маска из восьми стандартных (`MASKS`: `(x+y) mod 2`, `y mod 2`, `x mod 3`, `(x+y) mod 3`, `(⌊x/3⌋ + ⌊y/2⌋) mod 2`, `xy mod 2 + xy mod 3`, `(xy mod 2 + xy mod 3) mod 2`, `((x+y) mod 2 + xy mod 3) mod 2`, где x — столбец, y — строка) инвертирует только не-служебные модули;
   - `format(mask)` — информация о формате: 2 бита уровня (`FORMAT_M = 0`, у M это `00`) + 3 бита маски, 10 бит BCH(15,5) с многочленом `0x537`, XOR с `0x5412`. Две копии: вокруг левого верхнего поискового узора и разрезанная между правым верхним и левым нижним; плюс всегда тёмный модуль `(8, size−8)`.
8. **Выбор маски.** Для каждой из 8 масок (или только `opts.mask`) строится матрица и считается `penalty(m)`; берётся наименьший штраф. Правила штрафа:
   - N1: серия из 5 и более одинаковых модулей в строке или столбце — `длина − 2`;
   - N2: каждый одноцветный квадрат 2×2 — 3;
   - N3: каждое вхождение `10111010000` или `00001011101` в строке или столбце (похоже на поисковый узор) — 40; ищется только внутри матрицы, без поля вокруг;
   - N4: доля тёмных модулей: `(⌈|20·тёмные − 10·n²| / n²⌉ − 1) · 10` — по 10 за каждые 5 % отклонения от половины.
   Строки и столбцы обходит вложенная `line(get)`.
9. Результат — `{ version, mask, size, modules, score }`, `modules[y][x]` — `true` для тёмного.

Вывод:

- `toConsole(q, border = 2)` — для тёмной консоли: светлые модули (и поле вокруг кода, вложенная `light(x, y)`) рисуются символом, тёмные остаются фоном. Две строки модулей на строку текста: `█` (обе светлые), `▀` (верхняя), `▄` (нижняя), пробел. Поле — 2 модуля, а не стандартные 4. Для версии 3 это 33 столбца × 17 строк.
- `toSvg(q, border = 4)` — `<svg>` с `viewBox` `0 0 (size+8) (size+8)`, белый `<rect>` и один `<path>` из квадратов `M x y h1v1h-1z` на каждый тёмный модуль, `shape-rendering="crispEdges"`. Размер задаёт CSS страницы `/qr`.

`module.exports = { encode, toConsole, toSvg }`; пользуется только `serve.js`.

### `start.bat`

| Строка | Что делает |
|---|---|
| `@echo off` | не печатать сами команды |
| `rem …` (три строки) | описание; «ASCII only»: `cmd.exe` неверно читает кириллицу в `.bat`, поэтому все сообщения файла по-английски |
| `chcp 65001 >nul` | кодовая страница консоли — UTF-8; вывод `serve.js` — кириллица и символы `█▀▄` для QR. `>nul` прячет строку «Active code page: 65001» |
| `cd /d "%~dp0"` | перейти в папку файла, с переключением диска (`/d`): `node serve.js` должен найти `serve.js`, откуда бы ни запустили (ярлык, флешка) |
| `set PORT=%1` | порт из первого аргумента |
| `if "%PORT%"=="" set PORT=8779` | по умолчанию 8779 |
| `where node >nul 2>nul` | есть ли `node` в `PATH`; вывод и ошибки скрыты, итог — в `%errorlevel%` |
| `if %errorlevel%==0 (` … `)` | есть — `node tools\get-piper.js` (Piper: пробная фраза или загрузка, код выхода не смотрится), затем `node serve.js %PORT% --open --no-piper-download` (сервер с открытием браузера, без второй попытки качать Piper), после его выхода `goto :end` |

`set PORT` заодно ставит переменную окружения `PORT`, которую `serve.js` тоже понимает, но порт и так передаётся аргументом.

## Почему так, а не иначе

- **Без npm-зависимостей, QR — свой.** Очевидно было бы взять `express`, `qrcode`, `mime`. Но проект живёт на флешке и запускается на чужом ноутбуке без интернета: `npm install` там не сработает, а `node_modules` в копии проекта — лишние мегабайты и ещё одна точка отказа. Заголовок `serve.js`: «Только Node, без зависимостей: npm install не нужен»; `tools/qr.js` — «no dependencies». Кодировщик на 227 строк покрывает ровно то, что нужно: одну ссылку до 213 байт.
- **Один сервер вместо нескольких запускателей.** Комментарии «the one server» и «the one launcher» (`start.bat`) называют задачу: статика, студия, голос, мост к Ollama и QR — в одном процессе на одном порту. Альтернатива — отдельный статический сервер плюс отдельные прокси для голоса и модели — означала бы несколько окон, порядок запуска и CORS между ними. Совместимость с чужим статическим сервером оставлена только для голоса (`corsFor`).
- **`Cache-Control: no-cache` + ETag, а не `max-age` и не `no-store`.** Перезаписанная запись сохраняет имя файла, и студия имеет смысл, только если слышно то, что сохранено секунду назад (комментарий в `serveStatic`) — значит, долгий кеш нельзя. `no-store` заставлял бы каждый раз качать всё заново; `no-cache` с ETag даёт 304 на всё неизменённое — это важно телефону на слабом Wi-Fi. Тег строится из размера и `mtime`, поэтому новая запись меняет его сама.
- **gzip в процессе, уровень 9, с кешем.** JS и CSS презентации — около 1,1 МБ, сжатые — около 0,3 МБ; комментарий: именно это решает, сколько телефон на слабой связи ждёт первой рабочей кнопки. Уровень 9 дорог только при первом запросе файла — дальше ответ из `GZ_CACHE`. Звук, видео и картинки уже сжаты и идут как есть.
- **Диапазоны байтов.** Без `206` `<audio controls>` в студии не может перематывать.
- **Запись — только с этой машины, гостям — полигон и голос.** Презентацию может открыть кто угодно в сети, но перезаписать дубль или текст — только ведущий (заголовок файла). Полигон и голос гостям открыты, потому что жюри с телефона должно получить демку целиком; `--no-guests` закрывает и их.
- **«Эта машина» — loopback или свой адрес.** Презентация, открытая на ноутбуке по LAN-имени, приходит с LAN-адреса; проверка только на `127.0.0.1` сделала бы ведущего гостем (комментарий у `isLocal`).
- **Мост к Ollama, а не прямой запрос со страницы.** Тот же источник — Ollama не нужно настраивать `OLLAMA_ORIGINS`, а остановленная Ollama превращается в 502 с причиной вместо отказа соединения в консоли браузера (комментарий над `OLLAMA`).
- **Одна генерация за раз, очередь с `{"queued":n}`.** Процессор ноутбука, генерируя два ответа сразу, отдаёт оба поздно, и таймер первого слова на странице отправил бы оба в симуляцию. В очереди страница видит своё место и растягивает таймер (комментарий над `GEN`).
- **Ведущий впереди гостей.** Комментарий фиксирует правило: «The presenter (this computer) always goes ahead of the guests». Причина, по коду и ограничениям: презентацию ведёт один человек на общем экране, и её полигон не должен ждать десяток телефонов. Порядок между заданиями ведущего сохраняется, идущая генерация не прерывается.
- **Гостям — модель ведущего и короткие ответы.** Вторая модель в памяти ноутбука вытеснила бы первую и стоила бы минуты загрузки; `num_predict ≤ 200` ограничивает время, которое гость занимает очередь. Прогрев с телефона отвечается сразу: греть модель — дело ноутбука ведущего (комментарий). Один запрос с телефона и не больше 6 ждущих гостей — чтобы комната телефонов не держала очередь бесконечно.
- **Ключ ElevenLabs вне проекта и только на сервере.** Файл в профиле пользователя или переменная окружения: ключ не попадает ни на флешку, ни на хостинг, ни в страницу — браузер говорит только с `/api/tts` (комментарий над `TTS_DIR`). Цена HTTPS-сертификата с публичным ключом приемлема именно поэтому: через LAN не идёт ни одного секрета.
- **Конфиг перечитывается на каждый запрос.** Новый ключ в файле работает без перезапуска сервера (комментарий у `elevenConfig`).
- **Паузы после ошибок ElevenLabs.** Без них каждая реплика сначала ждала бы заведомо неудачного запроса (до 20 с таймаута); отказ по ключу не лечится за минуту, поэтому 5 минут, сетевая ошибка — 1 минута.
- **Лимит гостей по символам за запуск.** Комната телефонов не должна потратить месячные кредиты; после лимита гости слышат Piper, а уже озвученные фразы бесплатны (комментарий у `guestBudget`).
- **Дисковый кеш озвучки.** Фраза, сказанная один раз, второй раз ничего не стоит и звучит без интернета; README советует прогнать пресеты полигона один раз с сетью.
- **Piper по одному, без временных файлов.** Два Piper сразу на процессоре ноутбука медленные оба, а модель Ollama в это время всё равно занята (комментарий у `ttsQueue`). Сырой PCM в stdout и заголовок WAV в процессе — по коду видно, что так не нужны временные файлы и их уборка.
- **Piper — русский и английский, без таджикского.** Голоса — `ru_RU-irina-medium` и `en_US-lessac-medium`, по одному на язык (`VOICES` в `tools/get-piper.js`). Таджикского голоса в piper-voices нет: текст на `tj`/`tj_col` сервер Piper не отдаёт, а отвечает 503 с причиной — и страница говорит синтезом браузера. Новый язык — строка в `VOICES`, если для него есть голос; `serve.js` и страница узнают о нём из `/api/tts/info` (`piperVoices`).
- **CORS только с того же имени хоста.** Страница с другого статического сервера на этой машине должна найти голос на `:8779`; сайт из интернета — нет, иначе любая вкладка в браузере ведущего могла бы тратить кредиты ElevenLabs (комментарий у `corsFor`).
- **HTTPS через local-ip.sh.** Комментарий к блоку «the link for the jury's phones» даёт три причины против голого `http`: Chrome 154 (октябрь 2026) останавливает переход на публичные HTTP-сайты предупреждением, сканеры QR на телефонах не все считают голый IP ссылкой, а `getUserMedia` и подобное требуют защищённой страницы. Имя `<ip>.nip.io` для браузера публичное, хотя ведёт в частную сеть, — по HTTP оно и попадает под предупреждение; голые частные IP-адреса под это правило не подпадают, поэтому запасная ссылка — именно голый `http://<ip>/`, а nip.io остался только флагом `--nip`. local-ip.sh даёт настоящее имя с настоящим сертификатом на любой адрес, поэтому работает в любой сети, в том числе через точку доступа телефона. Цена — публичный закрытый ключ: годится для демо в LAN, не для продукта.
- **Ссылка считается по запросу, а не при старте.** Смена сети (точка доступа телефона) не требует перезапуска: `/qr` сразу показывает новый адрес. DNS-проверка кешируется на минуту, чтобы обновление страницы не ждало резолвер.
- **`:80` и `:443` по возможности.** Чтобы в ссылке для телефонов не было порта (комментарий у `listen80`): её короче читать с экрана и набирать руками. Занят порт или нет прав (Linux/macOS без root) — ссылка несёт порт, а не ломается.
- **Виртуальные адаптеры исключены.** Адрес VPN (`100.*` у Tailscale) или виртуальной сети в списке интерфейсов тоже есть, но телефон в той же Wi-Fi до него не достанет (комментарий у `lanAddresses`).
- **`/tools/*` не отдаётся.** Бинарник Piper и его голос на 63 МБ — инструменты сервера, а не ресурсы страницы (комментарий); там же лежат кеш озвучки и сертификат с ключом.
- **Манифест пересобирается при старте, а `GET /api/voice/manifest` — всегда в режиме путей.** Файлы могли подложить руками; а сохранённая секунду назад запись должна играть сразу, без пересборки base64 (комментарии у `server.listen` и у маршрута).
- **Субтитры пересчитываются сразу после сохранения.** Старые тайминги к новой записи акта рассинхронизируются; пересчёт занимает секунду-две на дорожку (комментарий у `retime`). Без ffmpeg запись всё равно сохраняется, а студия получает причину.
- **`start.bat` только ASCII.** `cmd.exe` неверно читает кириллицу в `.bat` (комментарий в файле); русский текст выводит уже `serve.js`.

## Функции

### `serve.js` — общие помощники

#### `retime(loc, id)` → `null | { ok: true, phrases, turns } | { ok: false, why }`
[serve.js:52](../../serve.js#L52). Для длинной дорожки (`lib.lineById(id).system === "media"`) пересобирает её субтитры: `cues.rebuild(loc, id)[0]`, пишет в консоль число фраз и реплик. Не дорожка → `null`; нет ffmpeg (`HAS_FFMPEG`) → `{ ok:false, why }` с подсказкой `node voice/cues.js`; исключение → `{ ok:false, why }` и строка в stderr. Синхронная: ffmpeg декодирует запись через `execFileSync`, сервер на это время (секунда-две) не отвечает никому. Зовут маршруты `take` и `text`.

#### `isLocal(req)` → `boolean`
[serve.js:89](../../serve.js#L89). Запрос с этой машины: `127.0.0.1`, `::1` или адрес любого её интерфейса (`os.networkInterfaces()` на каждый вызов — сменили сеть, проверка уже знает). Основа всех проверок доступа.

#### `clientIp(req)` → `string`
[serve.js:99](../../serve.js#L99). Адрес отправителя без префикса `::ffff:`. Ключ для `guestBusy` и `ttsBusy`.

#### `isLan(req)` → `boolean`
[serve.js:100](../../serve.js#L100). Частный адрес: `10/8`, `192.168/16`, `172.16/12`, `169.254/16`, весь `127/8`, IPv6 с началом `fc`, `fd` или `fe80`. Вместе с `GUESTS` решает, пускать ли гостя.

#### `corsFor(req)` → `null | { "Access-Control-Allow-Origin", "Vary", "Access-Control-Expose-Headers" }`
[serve.js:109](../../serve.js#L109). Нет `Origin` или он не разбирается → `null`. Сравнивает имя хоста `Origin` с `Host` без порта и квадратных скобок IPv6; вложенная `loop(h)` считает `localhost`, `127.0.0.1`, `::1` одним и тем же. Совпало → заголовки CORS с этим `Origin`. Зовётся только для путей `/api/tts*`.

#### `send(res, code, body, type, extra)`
[serve.js:121](../../serve.js#L121). Пишет весь ответ разом: тело (строка → UTF-8 `Buffer`), `Content-Type` (по умолчанию `text/plain; charset=utf-8`), `Content-Length`, `Cache-Control: no-store`; `extra` дополняет или переопределяет заголовки.

#### `json(res, code, obj)`
[serve.js:130](../../serve.js#L130). `send` с `JSON.stringify(obj)` и `application/json; charset=utf-8`.

#### `readBody(req, limit)` → `Promise<Buffer>`
[serve.js:132](../../serve.js#L132). Собирает тело запроса. Превышен `limit` → отклоняет с `lib.fail(413, "файл больше N МБ …")` и рвёт сокет (`req.destroy()`). Текст ошибки рассчитан на запись звука.

#### `readJsonBody(req)` → `Promise<object>`
[serve.js:145](../../serve.js#L145). Тело до 256 КБ как JSON; пустое → `{}`; не JSON → `lib.fail(400)`.

### `serve.js` — статика

#### `serveStatic(req, res, pathname)`
[serve.js:153](../../serve.js#L153). Отдаёт файл из `ROOT`: защита от выхода за корень (403) и от путей с сегментом на точку (404), ETag и 304, gzip через `GZ_CACHE`, один диапазон байтов (206/416), `HEAD`. Подробно — в «Статика». Сжатие при первом запросе файла синхронное (`readFileSync` + `gzipSync`).

### `serve.js` — API студии

#### `route(method, pattern, opts, fn)`
[serve.js:224](../../serve.js#L224). Регистрирует маршрут: регулярка `^pattern$`, флаги `local` и `guests` из `opts`. `fn(req, res, m, q)` получает совпадение регулярки `m` и `URLSearchParams` `q`; может быть `async` и бросать `lib.fail`.

Обработчики маршрутов студии (анонимные функции, [serve.js:228–322](../../serve.js#L228)) описаны таблицей в «Маршруты API». Что в них неочевидно:
- `GET /api/voice/pack`: метка времени имени файла собирается вложенной `p(n)` (дополнение нулём); `kind` — `""`, `-original` или `-added`; размер архива пишется в консоль строкой «архив».
- `POST /api/voice/take/…`: тип файла — только по заголовку `Content-Type` (часть до `;`, в нижнем регистре) через `lib.MIME_EXT`; содержимое не проверяется.
- `POST /api/voice/manifest`: без `inline=1` пишет режим путей; режим «оставить как есть» (`writeManifest()` без параметров) только при старте сервера и при сохранении записи.

### `serve.js` — мост к Ollama

#### `ollama(res, method, apiPath, body)`
[serve.js:340](../../serve.js#L340). Прокси одного запроса к `OLLAMA.host:OLLAMA.port`: статус и `Content-Type` Ollama, `Cache-Control: no-store`, тело потоком. Таймаут сокета 300 с. Ошибка до ответа → 502 `{ ok:false, why: "Ollama не отвечает на …" }`, после — обрыв ответа. Уход клиента обрывает запрос к Ollama. Параметр `body` вызывающие не передают (только `GET`).

#### `nextGen()`
[serve.js:375](../../serve.js#L375). Если генерация не идёт и очередь не пуста — снимает первое задание, ставит `GEN.busy`, сообщает оставшимся их места (`tell(i + 1)`) и запускает `job.start(done)`; `done` сбрасывает `busy` и снова зовёт `nextGen`.

#### Обработчик `POST /api/ollama/generate`
[serve.js:384](../../serve.js#L384). Проверки гостя, подмена модели и `num_predict`, постановка в очередь — см. «Очередь к Ollama». Методы задания:
- `job.tell(n)` — если клиент ещё здесь: при первом вызове заголовки 200 NDJSON, затем строка `{"queued":n}`.
- `job.start(done)` — снимает таймер очереди, отправляет тело в Ollama `/api/generate`, передаёт ответ потоком и дописывает `\n`; ошибки — 502 JSON или строка `{"error":…}`. Вложенная `finish()` гарантирует один вызов `done`.

### `serve.js` — голос без записи

#### `guestBudget(c)` → `number`
[serve.js:500](../../serve.js#L500). Лимит символов ElevenLabs для гостей: `ELEVENLABS_GUEST_BUDGET` или `c.guestBudget`; не число или меньше 0 → 3000.

#### `elevenConfig()` → `{ apiKey, voiceId, voiceName, model, settings, outputFormat, guestBudget? }`
[serve.js:506](../../serve.js#L506). Читает `ELEVEN_FILE` при каждом вызове (ошибка чтения или разбора → пустой конфиг), накладывает на `ELEVEN_DEFAULTS`, `settings` сливает по полям, ключ — `ELEVENLABS_API_KEY` или `apiKey` или `""`, голос и модель можно переопределить переменными окружения. #### `elevenSay(c, text, tag, voiceId)` → `Promise<Buffer>`
[serve.js:538](../../serve.js#L538). Запрос в ElevenLabs text-to-speech голосом `voiceId` (`c.voiceId` — Элис, `c.neikon.voiceId` — Нейкон): тег `tag` перед текстом (`MOOD_TAGS[mood]` у Элис, `NEIKON_TAG` у Нейкона, `""` — без тега), `model_id`, `voice_settings`, формат из `c.outputFormat`, `Accept: audio/mpeg`. 200 с непустым телом → звук; иначе `Error` с сообщением сервиса и `status`. Таймаут 20 с.

#### `wav(pcm, rate)` → `Buffer`
[serve.js:582](../../serve.js#L582). Заголовок RIFF/WAVE на 44 байта перед 16-битным моно-PCM: формат 1, `rate`, байт/с `rate·2`, выравнивание 2.

#### `piperSay(text, mood, v)` → `Promise<Buffer>` (WAV)
[serve.js:626](../../serve.js#L626). `v` — голос языка, `PIPER.voices[lang]`. Запуск Piper с `--model v.voice` и параметрами `MOODS[mood]` (по умолчанию `neutral`), текст в stdin, сырой PCM из stdout → `wav(pcm, v.rate)`. 30 с на всё; ошибка — с хвостом stderr или кодом выхода.

#### `ttsKey(parts)` → `string`
[serve.js:612](../../serve.js#L612). SHA-1 от `parts.join("|")` — имя файла в кеше.

#### `cached(key, ext)` → `null | { buf, ext }`
[serve.js:613](../../serve.js#L613). Кеш в памяти, затем файл `TTS_DIR/<key>.<ext>`; найденный на диске кладёт в память (без проверки размера `TTS_CACHE`).

#### `keep(key, buf, ext)` → `{ buf, ext }`
[serve.js:621](../../serve.js#L621). Кладёт звук в память (больше 60 — удаляет самый ранний) и на диск; ошибки записи молча пропускаются.

[serve.js:631](../../serve.js#L631). `elevenlabs.configured` — есть ключ; `paused` — идёт пауза после ошибки или (для гостя) лимит исчерпан; `why` — причина или `null`; `voice` — `voiceName` из конфига; `neikonVoice` — голос Нейкона (`c.neikon.voiceName`); `piper` — есть ли Piper хотя бы с одним голосом; `piperVoices` — язык → имя голоса (`{ ru: "ru_RU-irina-medium", en: "en_US-lessac-medium" }`), по нему страница решает, какие языки Piper прочтёт; `moods` — ключи `MOOD_TAGS`.

#### Обработчик `POST /api/tts`
[serve.js:644](../../serve.js#L644). Гость: второй запрос с того же IP, пока первый не закончен → 429 «этот телефон уже ждёт голос»; IP в `ttsBusy` на время `speakFor`, снимается в `finally`.

#### `speakFor(req, res, guest)`
[serve.js:700](../../serve.js#L700). Вся цепочка ElevenLabs → Piper → 503, см. «Голос без записи». `speaker: "neikon"` — голос `c.neikon.voiceId` с `NEIKON_TAG`, ключ кеша `["eleven", voiceId, model, settings, format, NEIKON_TAG, text]` (у Элис ключ прежний, с настроением, — её кеш не сбрасывается); без ElevenLabs — сразу 503 «у Нейкона нет офлайн-голоса», Piper не зовётся. Лимит гостей и пауза после ошибки общие на оба голоса. Пишет `eleven.guestChars`, `eleven.why`, `eleven.cooldownUntil`, `ttsQueue`, кеш.

#### `sendAudio(res, hit, engine, note)`
[serve.js:700](../../serve.js#L700). Ответ звуком: тип по `hit.ext` (`mp3` → `audio/mpeg`, иначе `audio/wav`), `no-store`, `X-TTS-Engine`, `X-TTS-Note` (URI-кодирован: в заголовке нельзя кириллицу).

#### `handleApi(req, res, pathname, q)`
[serve.js:711](../../serve.js#L711). Перебирает `routes` по порядку: метод, регулярка, `local` → 403, `guests` → 403, вызов с перехватом ошибок (`status` ошибки или 500, 5xx — в консоль). Ничего не подошло → 404 JSON.

## DOM, классы, события, хранилище

У сервера нет DOM и `localStorage`. Его «поверхность»:

- **Порты:** `PORT` (8779) на `0.0.0.0`; `:80`, если свободен; HTTPS `:443` или `:8443`. Только IPv4.
- **Адреса:** см. «Маршруты API», плюс `/qr`, `/studio.html` (только эта машина), `/tools/*` (всегда 404).
- **Заголовки ответа:** `ETag`, `Cache-Control: no-cache` (статика) / `no-store` (API), `Content-Encoding: gzip`, `Vary`, `Accept-Ranges`, `Content-Range`, `Content-Disposition` (ZIP, спикер-лист), `X-TTS-Engine`, `X-TTS-Note`, `Access-Control-*` (только `/api/tts*`).
- **Формат потока генерации:** `application/x-ndjson`, строки `{"queued":n}`, затем строки Ollama, `{"error":"…"}` при обрыве.
- **Внешние адреса:** `api.elevenlabs.io` (`/v1/text-to-speech/…`), `https://local-ip.sh/server.pem` и `server.key`, DNS `*.local-ip.sh` и `*.nip.io`, Ollama на `OLLAMA_HOST`.
- **Файлы:** `tools/tts-cache/`, `tools/https/` (пишет), `tools/piper/` (читает), `~/.terminal-shattered/elevenlabs.json` (читает), всё, что пишут `voice/lib.js` и `voice/cues.js`.
- **Процессы:** Piper (`spawn`, скрытое окно), браузер (`exec`), ffmpeg (через `voice/cues.js`).
- **Классы страницы `/qr`:** `figure.main`, `figure.alt`, `.code`, `.others`.
- **Сигналы:** `Ctrl+C` в окне — остановка; отдельной обработки нет.

## Подводные камни

**Порядок и состояние**

- Всё, что проверяется один раз при старте, после изменения требует перезапуска: `HAS_FFMPEG` (поставили ffmpeg), `PIPER.ok` (положили Piper руками — фоновая загрузка, наоборот, включает его сама), `OLLAMA` (сменили `OLLAMA_HOST`), сертификат (`ensureTls` только при старте; обновится на следующем запуске). Конфиг ElevenLabs, наоборот, перечитывается на каждый запрос.
- `eleven.guestChars` живёт в памяти: перезапуск сервера обнуляет лимит гостей.
- `GET` и `POST /api/voice/manifest` — один путь, разные действия; `handleApi` различает их по методу. Новый маршрут с той же регуляркой и методом никогда не сработает: побеждает первый зарегистрированный.
- Задание ведущего встаёт перед гостями, но не прерывает идущую генерацию гостя: ведущий ждёт не дольше одного гостевого ответа (`num_predict ≤ 200`).
- Если ведущий ещё ни разу не спрашивал модель (`GEN.lastModel === null`), гость идёт со своей моделью — и может загрузить в память вторую. Полигон на ноутбуке стоит открыть до того, как раздать QR (README и так требует открыть его перед выступлением).
- Успешный запрос с `engine: "elevenlabs"` во время паузы очищает `eleven.why`, но не `cooldownUntil`: до конца паузы режим `auto` по-прежнему идёт в Piper, а `X-TTS-Note` говорит «пауза после ошибки».

**Сеть и доступ**

- Сервер слушает только IPv4 (`0.0.0.0`): ветки `::1` в `isLocal` и IPv6-диапазоны в `isLan` на практике не срабатывают.
- `/api/voice/info`, `/api/voice/manifest` и `/api/lan` открыты без проверки адреса — любому, кто достучался до порта. `/api/lan` отдаёт имена адаптеров и адреса ноутбука.
- `--nip` выключает HTTPS: две ссылки одновременно не бывает.
- Ссылка `https://…local-ip.sh` выбирается, если имя резолвится резолвером ноутбука. Вероятный сбой (вывод, не из кода): роутер с защитой от DNS rebinding отбрасывает ответы с частными адресами для телефонов, а ноутбук пользуется другим DNS — тогда `/qr` покажет `https`, а телефон имя не найдёт. Лечится `--no-https`.
- `fetchText` не идёт по редиректам: если local-ip.sh начнёт перенаправлять, сертификат перестанет скачиваться (старый проработает до конца срока).
- `OLLAMA_HOST` со схемой `https://` разбирается, но запрос всё равно идёт по `http`.
- На Node 18.0–18.3 `os.networkInterfaces()` отдавал `family` числом `4`, а `lanAddresses()` сравнивает со строкой `"IPv4"` — там ссылок для телефонов не будет (особенность Node, не кода проекта).

**Производительность**

- `retime()` синхронный: на секунду-две после сохранения записи или текста акта сервер не отвечает никому, включая поток модели на телефоны.
- Первое сжатие файла — синхронный `gzipSync` уровня 9; после смены файла (новый `mtime`) — снова. В `GZ_CACHE` до 200 файлов, вытесняются самые ранние по вставке, не по использованию.
- `cached()` кладёт найденное на диске в `TTS_CACHE` без проверки размера; лишнее срежет только следующий `keep()`.

**QR**

- `encode` с явным `opts.version` не проверяет ёмкость: слишком длинный текст молча обрежется при размещении. `serve.js` версию не задаёт.
- Поле `toConsole` — 2 модуля вместо 4 по стандарту; на светлой теме консоли код будет инвертирован (светлые модули рисуются символами) и может не читаться.
- QR в консоли печатается один раз при старте; после смены сети актуален только `/qr`.

**Расхождения и вероятные ошибки** (найдены при чтении, код не правился)

1. [serve.js:732–752](../../serve.js#L732): `new URL(req.url, "http://localhost")` стоит вне `try`. Цель запроса, которую WHATWG URL не разбирает (например, `//[`), бросает `ERR_INVALID_URL` прямо в обработчике `request` — вероятно, это неперехваченное исключение и падение процесса от одного кривого запроса из сети. Не проверялось запуском.
2. [serve.js:748–750](../../serve.js#L748): защита `/tools/` и `/studio.html` сравнивает сырой путь с учётом регистра и до `decodeURIComponent`, а `serveStatic` декодирует путь сам. `/%74ools/tts-cache/…` (проверено: `new URL` оставляет `%74`, `decodeURIComponent` даёт `/tools/…`) и на Windows `/Tools/…` доходят до `tools/`: кеш озвучки, Piper, `tools/https/server.key` (ключ публичный и так). Комментарий [serve.js:771](../../serve.js#L771) «tools/ is never served» и ARCHITECTURE («не отдаётся наружу») это не учитывают. `/Studio.html` по той же причине открывается гостю (API студии всё равно 403).
3. [serve.js:138](../../serve.js#L138): при превышении лимита `readBody` зовёт `req.destroy()`, после чего `handleApi` пытается ответить 413 в уничтоженный сокет — клиент, вероятно, получит обрыв соединения, а не текст ошибки. Текст рассчитан на звук: для JSON (256 КБ) и тела гостя в `generate` (64 КБ) он скажет «файл больше 0 МБ … сохраните в mp3».
4. [serve.js:416–425](../../serve.js#L416): если Ollama упадёт посреди потока, у ответа `r` не будет `end`, а у запроса `up` — `error` (в Node ответ в этом случае уничтожается без `error`-события, если нет слушателя). `finish()` не вызовется, `GEN.busy` останется `true`, пока страница сама не оборвёт запрос по своему таймеру. По коду — очередь самовосстанавливается только через клиента.
5. [serve.js:509](../../serve.js#L509), [serve.js:988](../../serve.js#L988): `voiceName` не меняется вместе с `voiceId` (ни из файла без `voiceName`, ни из `ELEVENLABS_VOICE_ID`) — `/api/tts/info` покажет «Milly Maple» для другого голоса; баннер пишет «Milly Maple» жёстко.
6. [serve.js:536](../../serve.js#L536), [serve.js:671](../../serve.js#L671), [serve.js:702](../../serve.js#L702): `outputFormat` можно переопределить, но ответ ElevenLabs всегда кешируется как `.mp3` и отдаётся как `audio/mpeg`, а запрос шлёт `Accept: audio/mpeg`. Формат не-MP3 (`pcm_*`, `ulaw_*`) сломает воспроизведение.
7. [serve.js:856](../../serve.js#L856): сообщение «local-ip.sh отдал сертификат, который не подходит — оставляю http» печатается и тогда, когда старый сертификат ещё действует и HTTPS поднимется с ним.
