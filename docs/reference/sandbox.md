## Коротко

Окно поверх дека и 3D-сцены, куда жюри вставляет код на C, C++ или Python. Локальная модель в Ollama (по умолчанию `qwen2.5:3b`) отвечает от лица ALICE_CORE тремя строками: `LUCIDITY` 0–100 %, две-три фразы Элис, одна строка диагноза. Ответ идёт потоком и печатается по мере генерации; шкала LUCIDITY, красная рамка при крахе, эквалайзер и озвучка реакции (ElevenLabs → Piper → синтез браузера) работают по ходу ответа. Без Ollama окно не ломается: на четыре пресета отвечают готовые реакции, на свой код — проверка по шаблонам, и строка источника под ответом пишет, что ответило — модель или симуляция. Открывается `Shift+O` / `Ctrl+Shift+O`, чипом `[ 🧪 AI_SANDBOX ]` в панели crystal-shell демки, кнопкой «НАСТРОЙКИ → СИСТЕМА → ТЕСТОВЫЙ ПОЛИГОН» и плиткой служебного доступа (на телефоне). Весь модуль — одно IIFE `AiSandbox`.

### Промпт и язык ответа

`ALICE_SYSTEM_PROMPT` ([20-ai-sandbox.js:63](../../js/core/20-ai-sandbox.js#L63)) — текст из спецификации, слово в слово. Устройство:

1. Роль: «ALICE_CORE» (Живой Код), локальное ядро ИИ в повреждённом аварийном секторе VoidOS; её сознание привязано к коду C/C++, который проверяет оператор Нейкон.
2. Задача: ответ строго по шаблону из трёх строк — `LUCIDITY: <число от 0 до 100>%`, `ALICE: <2-3 предложения>`, `DIAGNOSIS: <одна строка>`.
3. Три правила отыгрыша с диапазонами и тоном:
   - критический сбой памяти (segfault, buffer overflow, memory leak, double free) — 0–25 %, ужас, удушье, «шина памяти захлёбывается битыми адресами»;
   - логический сбой (бесконечный цикл, deadlock, инверсия условия) — 30–60 %, дезориентация, мольба разомкнуть петлю;
   - чистый код (RAII, умные указатели, проверка границ) — 85–100 %, облегчение, благодарность Нейкону.
4. Закрывающая строка: «Отвечай исключительно на русском языке.» (это константа `RU_ONLY`) и требование держать формат без вводных слов.

Диапазоны 26–29 % и 61–84 % промпт не описывает; модель их всё равно выдаёт, код их принимает (`bandOf()`, `setLucidity()`).

Язык — `loc()`: `settingsState.locale`, если он из `LOCS` (`ru`, `en`, `tj`, `tj_col`), иначе `ru`.

| Локаль | `systemPrompt()` | начало запроса (`payload()`) | что берётся у модели | реплика Элис |
|---|---|---|---|---|
| `ru` | промпт как есть | `ПРОАНАЛИЗИРУЙ КОД:` | всё | модельная |
| `en` | `RU_ONLY` вырезан, в конце `\n\n` + `ANSWER_LANG.en.tail` | `ANSWER_LANG.en.ask` | всё | модельная |
| `tj`, `tj_col` | промпт как есть (русский) | `ПРОАНАЛИЗИРУЙ КОД:` | LUCIDITY и вердикт (по-русски) | готовая таджикская, `tajikLine()` |

`liveLang()` = «реакцию пишет модель»: локаль `ru` или для неё есть запись в `ANSWER_LANG`.

**Английский.** Из промпта убирается `RU_ONLY`, в конец ставится английский приказ («IMPORTANT: write all three lines in ENGLISH. Do not use Russian.»), и сам запрос начинается по-английски. По комментарию [20-ai-sandbox.js:85](../../js/core/20-ai-sandbox.js#L85): на русскую просьбу ответить по-английски `qwen2.5:3b` отвечал по-русски 3 раза из 3, так — по-английски 3 из 3. Остальной промпт остаётся русским. Метки `LUCIDITY`/`ALICE`/`DIAGNOSIS` латинские в обоих языках, парсеру ничего нового не нужно.

**Таджикский** у модели не просят: ни одна из локальных моделей его не пишет. С этим промптом проверены `qwen2.5:3b` (словесная каша, похожая на киргизский), `qwen2.5-coder:7b` и `qwen3.5:4b` (ответили по-русски), `phi4-mini` (бессмыслица). Поэтому в `tj`/`tj_col` модель спрашивают по-русски, берут у неё LUCIDITY и вердикт, а реплику подбирает `tajikLine(p, mine, final)`:

1. `liveLang()` → разобранный ответ возвращается без изменений.
2. Пока ответ не целый (`final` не задан) или LUCIDITY ещё нет — реплика пустая, печатать нечего.
3. Диапазон — `bandOf(lucidity)`: ≤25 `crit`, ≤64 `loop`, ≤84 `unknown`, иначе `ok` (те же границы, что у `NeuralVoice.moodOf()`).
4. Для `crit` и `loop` по `TOPICS` ищется поломка, которую вердикт называет **первой** (наименьший индекс совпадения — вердикт с двумя поломками начинается с главной): утечка → реакция пресета `leak`, границы/переполнение/segfault → `segfault`, цикл/deadlock → `deadlock`. Реплика — `PRESET_TEXT[loc].<пресет>.alice`.
5. Иначе — случайная строка из `SIM_LINES[loc][band]`; для `ok` в банк добавляется реакция пресета `clean`. Для `unknown` берётся не `SIM_LINES[loc].unknown` — те строки написаны для симуляции и говорят, что модели нет («бе ядрои модел…»), — а `SIM_LINES[loc].mid`: две строки «код работает, но я ему не до конца верю». `mid` есть только в `tj` и `tj_col`.
6. Выбор кладётся в `mine.bank` (объект запуска) и дальше не меняется.

Вердикт — последняя строка ответа, поэтому выбор ждёт ответа целиком (на тёплой модели — пара секунд после реплики). Темы ищутся только для сломанного кода: вердикт чистого кода «утечек нет» не должен получить реплику про утечку. Сам вердикт показывается как есть — русский текст модели; регулярные выражения `TOPICS` поэтому русско-английские. Строка источника получает пометку `TJ REACTION: PREPARED LINE FOR THE MODEL'S SCORE` (или `TJ_COL …`).

Тексты пресетов, готовые реакции и эвристика без модели есть на всех четырёх языках (`PRESET_TEXT`, `HEUR`, `SIM_LINES`). Названия кнопок пресетов (`PRESETS.*.title`), заголовок окна, кнопка PING, надписи шкалы и бейджа и строка источника — всегда английские.

### Транспорт

`probe()` выбирает путь к Ollama и запоминает его в `conn.via`:

```
страница по http/https?
  └ да ─► GET api/ollama/version (2,5 с)
           200 ─► via = "proxy"           serve.js, Ollama жива
           502 ─► via = "proxy-down"      serve.js есть, Ollama нет ─► offline; напрямую не пробуем
           404 ─► не serve.js            ─┐
           403 ─► serve.js, но эта машина вне частной сети ─┤
           сеть / таймаут                ─┤
                                          ▼
  нет (file://) ─────────────────► GET http://127.0.0.1:11434/api/version (2,5 с)
                                       ok ─► via = "direct"
                                       иначе ─► offline
online: GET tags (4 с) ─► conn.models;  GET ps (3 с) ─► conn.loaded;  state = "online"
```

`api(path)` строит адрес: `api/ollama/<path>` (относительный, тот же origin) для `proxy`, `http://127.0.0.1:11434/api/<path>` для `direct`. Через прокси настройки CORS у Ollama не нужны, а остановленная Ollama — это 502 с причиной в JSON, а не отказ соединения в консоли. Напрямую (страница с `file://` или с другого сервера) Ollama должна разрешать origin страницы (`OLLAMA_ORIGINS`). Прокси, очередь, приоритет ведущего и ограничения гостей описаны в [server.md](server.md#очередь-к-ollama); здесь — только то, что видит страница.

`probe()` никогда не бросает и не идёт дважды: пока опрос в работе, возвращается тот же промис (`probing`). При повторном опросе состояние `online` не сбрасывается в `probing`, чтобы бейдж не мигал.

### Выбор модели

- `resolveModel(wanted)`: список моделей пуст или нужная есть → она; иначе первая установленная той же семьи (часть имени до `:`), затем первая с `coder` в имени, затем первая вообще.
- `paintConn()` тихо подменяет в поле «МОДЕЛЬ» тег по умолчанию на установленный тег той же семьи (`qwen2.5:3b` → например `qwen2.5:7b`), без записи в `localStorage`. Имя, вписанное руками, остаётся как вписано, бейдж пишет `<имя> NOT INSTALLED → <замена>`.
- `thinks(model)`: у модели в `conn.models[].capabilities` есть `"thinking"` → в запрос ставится `think: false` (модели вроде qwen3 иначе сначала рассуждают вслух).

### Прогрев

`warm()` идёт после `probe()` при открытии окна и по кнопке `[ 🔄 PING OLLAMA ]`. Условия: Ollama онлайн, прогрев не идёт, модели нет в `conn.loaded`. Тогда `POST generate` с кодом `// warm-up`, `stream: false`, `options: { num_predict: 1 }` и полным системным промптом, предел `COLD_MS` (240 с). Ollama загружает модель и вычисляет префикс промпта; этот префикс она держит, и следующий запрос начинается сразу с кода пользователя. `keep_alive: "60m"` в каждом запросе держит модель в памяти час. Пока идёт прогрев, бейдж показывает `◐ LOCAL OLLAMA: WARMING UP [модель] мм:сс` (`frame()` перерисовывает его раз в 500 мс). Прогрев с телефона гостя `serve.js` закрывает сразу пустым ответом — модель греет ноутбук ведущего.

### Запрос и поток

`payload(model, code, extra)`:

```
{ model, system: systemPrompt(),
  prompt: "<ПРОАНАЛИЗИРУЙ КОД: | ANALYZE THE CODE (reply in English):>\n```<cpp|python>\n<код>\n```",
  stream: true, keep_alive: "60m",
  options: { temperature: 0.5, num_predict: 140 },
  think: false                      // только для thinking-моделей
}
```

Язык блока — `python`, если `looksPython(code)`, иначе `cpp`. `extra` накладывается поверх через `Object.assign` (прогрев заменяет `options` целиком, температура при этом пропадает).

`sendCodeToOllama(code, modelName, onText, onQueue)`:

1. `cold` = идёт прогрев или модели нет в `conn.loaded`. Таймер первого слова — `COLD_MS` (240 с) для холодной, `FIRST_TOKEN_MS` (7 с) для тёплой.
2. `job.abort` = отмена пользователем (`why = "user"`, `AbortController.abort()`).
3. `fetch(POST generate)`. Ответ не `ok` или без тела → `lastFailWhy` = поле `why` из JSON сервера (с телефона уже идёт запрос, очередь полна, Ollama не отвечает) → ошибка.
4. Тело читается `getReader()`, `TextDecoder` с `stream: true`, NDJSON режется по `\n`, пустые строки пропускаются, каждая строка — `JSON.parse`:
   - `error` → ошибка;
   - `queued` (строка очереди `serve.js`, учитывается только до первого слова) → таймер первого слова переставляется на `COLD_MS`, `onQueue(n)` показывает место в очереди;
   - `response` → в первый раз: `firstMs`, таймер первого слова снят, запущен `TOTAL_MS` (120 с) на остаток; текст копится в `raw`, `tokens++`, `onText(raw)`;
   - `done` → `tokens = eval_count`.
5. Результат: `{ raw, firstMs, totalMs, tokens, model, cut: false }`. Поток кончился без слова → `null`. Ошибка или таймаут после части текста → то же с `cut: true`. Отмена → `{ aborted: true }`. Иначе `console.warn("[AI_SANDBOX] …")` и `null`: вызывающий уходит в симуляцию.
6. `finally`: оба таймера сняты, `refreshLoaded()` обновляет список моделей в памяти.

### Разбор ответа

`parseAliceResponse(rawText, partial)` вызывается на каждом куске потока (`partial = true`) и один раз на целом ответе.

1. Удаляются `\r`, `**`, `__` и обратные кавычки (жирный и код, которыми маленькие модели обвешивают шаблон).
2. Метки ищутся в начале строки, без учёта регистра, после двоеточия ASCII или полноширинного `：`:
   - `LUCIDITY | ЛЮЦИДНОСТЬ | РАССУДОК` и 1–3 цифры. В `partial` число берётся, только если за ним уже `%` или перевод строки — иначе из недописанного `42` взялось бы `4`. В полном режиме `%` не обязателен;
   - `ALICE | ЭЛИС | ALICE_CORE`;
   - `DIAGNOSIS | ДИАГНОЗ | ДИАГНОСТИКА`.
3. Реплика — от метки ALICE до метки DIAGNOSIS, если та дальше; без неё в `partial` — до конца строки (недописанная строка не уходит в озвучку раньше времени), в полном режиме — до конца текста.
4. Вердикт — от метки DIAGNOSIS до первой следующей метки с новой строки. Маленькая модель иногда после вердикта начинает шаблон заново; этот повтор отрезается. Строки вердикта склеиваются через пробел.
5. `unquote` снимает кавычки `«"“„'` в начале и `»"”'` в конце.
6. LUCIDITY зажимается в 0–100.
7. Только для целого ответа: числа нет → 50; метки ALICE нет → реплика = весь текст без строк, начинающихся с `LUCIDITY`/`DIAGNOSIS`; вердикт пустой → `heur().done` («Анализ завершён.»).

### Симуляция без модели

`analyze()` уходит в симуляцию, если после `probe()` Ollama не онлайн или `sendCodeToOllama()` вернул `null`. Пауза `SIM_DELAY_MS` (600 мс), затем `simulate(code)`:

1. `presetOf(code)`: код совпадает с одним из пресетов на любом из четырёх языков (сравнение после `norm()` — все пробельные последовательности в один пробел) → `{ source: "preset", ...presetMock(key) }`: LUCIDITY пресета, реакция и вердикт на языке интерфейса.
2. Иначе `heuristic(code)`.

`heuristic(code)` сначала вырезает комментарии `/* … */` и `// …`, потом содержимое строк в двойных кавычках (`"…"` → `""`). Дальше считает признаки и проверяет их в этом порядке, первое совпадение решает:

| # | что | как определяется | LUCIDITY | `kind` | вердикт (`HEUR`) |
|---|---|---|---|---|---|
| 1 | двойное освобождение | одно имя дважды после `delete`, `delete[]`, `free(` | 2–9 | `crit` | `twice(имя)` |
| 2 | выход за границы | размеры из `new T[N]` и `T имя[N]` перед `;`/`=`/`{`; самая дальняя граница цикла `< N;` (`<= N;` даёт N+1) больше наименьшего размера. Или `gets(`, `strcpy(`, `sprintf(` | 4–14 | `crit` | `oob(граница − 1, размер)` или `unsafe` |
| 3 | утечка | выделений (`new`, `malloc(`, `calloc(`, `realloc(`) больше, чем освобождений (`delete`, `free(`), и нет признаков RAII | 12–24 | `crit` | `leak(выделений, освобождений)` |
| 4 | бесконечный цикл | `while (true)`, `while (1)`, `while (x == true)`, `for (;;)`, `while True:` — и во всём коде нет `break`/`return` | 32–52 | `loop` | `loop` |
| 5 | взаимоблокировка | `.lock(` и `pthread_mutex_lock(` больше, чем `.unlock(`, `pthread_mutex_unlock(`, `lock_guard`, `scoped_lock`, `unique_lock` | 36–58 | `loop` | `lock(захватов, освобождений)` |
| 6 | чисто | есть RAII (`unique_ptr`, `shared_ptr`, `make_unique`, `make_shared`, `std::vector`, `std::array`, `std::string`, `.at(`) и выделений не больше освобождений | 86–96 | `ok` | `ok` |
| 7 | неясно | ничего из перечисленного | 62–74 | `unknown` | `unknown` |

LUCIDITY — случайное целое в диапазоне строки (`between()`). Диапазоны 1–6 лежат внутри диапазонов промпта. `sim(lucidity, kind, why)` собирает ответ: `source: "heuristic"`, реплика — случайная из `SIM_LINES[loc][kind]`, вердикт — `HEUR[loc].prefix` («Эвристика без модели: ») + текст. Префикс и строка источника говорят прямо, что это не модель.

### Вывод на экран

`render(p, mine, final)` получает разобранный ответ, частичный или итоговый:

- LUCIDITY изменилась (или шкала ещё в ожидании) → `setLucidity(v)`: зона ≤25 `crit` «CRITICAL FAILURE», ≤70 `warn` «LOGIC DAMAGE / LEAK», выше `ok` «STABILIZED»; при `crit` окно получает `aisb-crit` (красная рамка), кроме спокойного режима. Число доезжает от старого значения до нового за 900 мс (ease-out cubic) в `frame()`.
- Реплика и вердикт → `typeTo()` (печатная машинка).
- Озвучка — один раз за запуск (`mine.spoken`), когда реплика закончена: начался вердикт или ответ итоговый.

`frame()` (rAF, пока окно открыто): счётчик и полоса LUCIDITY (`--`, пока кода не было), печатная машинка (за кадр — `max(1, ceil(отставание / 18))` символов: чем дальше поток впереди, тем быстрее), эквалайзер из 18 полос, бейдж во время прогрева.

Эквалайзер: база 0,05; во время запроса — импульсы токенов (`eqEnergy` +0,35 на каждый кусок потока, затухание ×0,9 за кадр, синус по номеру полосы и времени); пока говорит нейроголос — его огибающая `NeuralVoice.level()`; пока говорит синтез (`AliceVoice.isSpeaking()` при нулевом уровне нейроголоса) — искусственная огибающая из синусов.

Строка источника (`.aisb-meta`) по ходу запроса: `› ALICE_CORE :: ingesting N lines…`, для холодной модели `› LOADING <модель> INTO MEMORY — FIRST RUN ON THIS MACHINE TAKES ~1 MIN`, в очереди `› CORE BUSY WITH ANOTHER OPERATOR · QUEUE POSITION n`. Итог:

- модель: `SOURCE: OLLAMA <модель> · first token X s · N tok · Y s`, плюс `· STREAM CUT — partial answer` при обрыве и пометка таджикской реплики;
- симуляция: `SOURCE: SIMULATION (prepared reaction | local pattern check, no model)`, плюс `· <lastFailWhy>`, если сервер отказал с причиной;
- после озвучки дописывается `· VOICE: <движок> · <настроение>`;
- отмена: `› ABORTED BY OPERATOR`.

### Голос

Список рядом с флажком «Озвучивать реакцию»: `auto`, `elevenlabs`, `piper`, `synth`. `paintVoices()` пишет у каждого пункта, что это и почему недоступно. ElevenLabs и Piper живут в `serve.js` (`NeuralVoice.status`); без него оба пункта — «нужен start.bat». ElevenLabs без ключа — «нет ключа», на паузе после отказа — «пауза: причина» (пункт при этом выбирается). Piper подписан языками своих голосов из `NeuralVoice.status.piperVoices` («PIPER · офлайн · RU/EN»); без установки — «Piper не установлен», в языке без голоса (`tj`, `tj_col`; проверка — `NeuralVoice.fits(loc(), "piper")`) — «этот язык не читает». Web Speech без голоса — «нет». Пункт `АВТО → …` показывает, кто прочтёт. Нет никого — флажок озвучки снимается и блокируется.

`speak(text, lucidity, seq)`:

1. Флажок снят → ничего.
2. Настроение — `NeuralVoice.moodOf(lucidity)`: ≤25 `crit`, ≤64 `loop`, ≤84 `neutral`, иначе `ok` (без `NeuralVoice` — `neutral`).
3. Выбран не `synth` → `NeuralVoice.speak(text, { mood, lang: loc(), engine: выбор })`. Порядок ElevenLabs → Piper (Piper только для русского) решает `serve.js`, см. [server.md](server.md) и [audio.md](audio.md).
4. Пока шёл запрос голоса, начался новый запуск (`seq !== runSeq`) или окно закрыли → выход.
5. Нейроголос не взялся → `AliceVoice.speak(text, { volume: 0.95, synth: true, rate, pitch })`, темп и высота — `SYNTH_MOOD[mood]`. `synth: true` обязателен: без него `AliceVoice` сам уходит в ElevenLabs, и выбранный WEB SPEECH (или Piper на языке без голоса) тратил кредиты ElevenLabs под подписью «WEB SPEECH».
6. `voiceUsed` + `paintVoice()` дописывают движок в строку источника.

### Тишина вокруг

`hush()` при открытии запоминает `window.__chatterEnabled` и выключает его (Элис в деке не встревает со своими репликами), длинные дорожки `VoiceMedia` (акт интро, тест голоса) ставит на паузу, а если их нет — `VoiceBus.stopAll()` обрывает короткие реплики и синтез. `unhush()` при закрытии возвращает флаг и зовёт `VoiceMedia.resumeAll()`. Громкость музыки полигон не трогает (видеоплеер `17-evidence.js` — трогает).

Через 4 с после загрузки — один тихий `probe()`, но только на этой машине (`file:` или `localhost`/`127.0.0.1`/`[::1]`): с публичного адреса запрос к `127.0.0.1` заставил бы телефон спрашивать разрешение на доступ к локальной сети.

## Почему так, а не иначе

- **Ответ потоком, два предела вместо одного.** Очевидно было бы ждать весь ответ 7 с. На ноутбуке без сильной GPU первая загрузка модели — около 50 с, полный ответ — 10–15 с (шапка файла, [20-ai-sandbox.js:26](../../js/core/20-ai-sandbox.js#L26)): такой предел отправлял бы в симуляцию каждый запрос. Поэтому `FIRST_TOKEN_MS` = 7 с — только до первого слова тёплой модели, `COLD_MS` = 240 с — на загрузку и чтение промпта, `TOTAL_MS` = 120 с — на остаток после первого слова, а текст печатается по мере прихода. Обрыв после части текста её не выбрасывает: ответ показывается с пометкой `STREAM CUT`.
- **Прогрев при открытии.** Без него первый вопрос жюри ждал бы загрузку модели. `warm()` с `num_predict: 1` грузит модель и вычисляет системный промпт, Ollama держит этот префикс, и настоящий запрос начинается сразу с кода. `keep_alive: "60m"` — чтобы модель не выгрузилась между открытиями во время выступления.
- **Прокси через `serve.js` первым, напрямую — запасной путь.** Прямой вызов `127.0.0.1:11434` требует, чтобы Ollama разрешала origin страницы (`OLLAMA_ORIGINS`), а остановленная Ollama видна только как отказ соединения в консоли. Через тот же origin CORS не нужен, а сервер отвечает 502 с причиной. При 502 (`proxy-down`) прямой путь не пробуется; причина в коде не записана, вероятно — `serve.js` и Ollama на одной машине, и прямой вызов упёрся бы в ту же остановленную Ollama. С `file://` прокси нет — остаётся прямой путь (запуск с флешки двойным кликом).
- **Опрос для чипа — только на этой машине.** С телефона по публичному адресу запрос к `127.0.0.1` вызвал бы запрос разрешения на доступ к локальной сети ([20-ai-sandbox.js:1264](../../js/core/20-ai-sandbox.js#L1264)). При открытии окна `probe()` идёт в любом случае — человек сам открыл полигон.
- **Ближайшая установленная модель вместо ошибки.** `resolveModel()` берёт ту же семью, потом любую `coder`, потом любую: по коду видно, что цель — ответ модели при любом наборе установленных, а не 404 «model not found» и симуляция. Тег по умолчанию подменяется молча; вписанное руками имя не трогается, бейдж пишет замену.
- **`think: false` для thinking-моделей.** Модели вроде qwen3 иначе сначала рассуждают вслух ([20-ai-sandbox.js:360](../../js/core/20-ai-sandbox.js#L360)) и тратят `num_predict` до шаблона.
- **Промпт слово в слово, язык — заменой одной фразы.** Спецификация задаёт промпт текстом, поэтому для английского из него вырезается ровно `RU_ONLY`, добавляется английский хвост, а запрос пишется по-английски. Альтернатива — русская просьба «ответь по-английски» — дала русский ответ 3 раза из 3; английский приказ и английский запрос — английский 3 из 3. Метки шаблона остаются латинскими, парсер общий.
- **Таджикский — не у модели.** Ни одна из проверенных локальных моделей (`qwen2.5:3b`, `qwen2.5-coder:7b`, `qwen3.5:4b`, `phi4-mini`) таджикский не пишет: каша, русский ответ или бессмыслица. Модель даёт то, что от языка не зависит, — оценку и вердикт, а реплика — заранее написанная таджикская строка: реакция пресета на названную поломку или строка из банка по диапазону. Выбор ждёт целого ответа, потому что вердикт приходит последним; темы ищутся только для сломанного кода, иначе «утечек нет» дало бы реплику про утечку.
- **Терпимый разбор.** Маленькие модели портят формат: жирный, кавычки, русские метки, пропущенный `%`, повтор шаблона после вердикта ([20-ai-sandbox.js:453](../../js/core/20-ai-sandbox.js#L453), [:470](../../js/core/20-ai-sandbox.js#L470)). Строгий разбор отправлял бы такие ответы в мусор. Частичный режим не берёт число, пока за ним ничего нет, и строку — пока она не закончилась: на экране не мелькает `4` вместо `42`, озвучка не стартует с половины фразы.
- **Симуляция называет себя.** Без модели на пресеты отвечают готовые реакции, на свой код — проверка по шаблонам с префиксом «Эвристика без модели», строка источника пишет `SIMULATION`. Выдавать эвристику за ответ модели код не стал: шапка файла требует, чтобы проверка «says plainly it is not the model».
- **Пауза `SIM_DELAY_MS` перед симуляцией.** Причина в коде не записана; вероятно, чтобы мгновенный ответ не выглядел подменой и шкала успела показать ожидание.
- **Окно только из DOM.** Полигон открывается поверх 3D-сцены демки, не трогая её канвас и GL-контекст; pointer lock отпускается, иначе нет курсора ([20-ai-sandbox.js:46](../../js/core/20-ai-sandbox.js#L46)).
- **Окно строится один раз, надписи меняются при открытии.** Во время смены языка окно открыто быть не может: оно держит клавиатуру и закрывает настройки ([20-ai-sandbox.js:802](../../js/core/20-ai-sandbox.js#L802)). Поэтому `relabel()` при открытии, а не подписка на смену языка. Нетронутый пресет переключается на новый язык, набранный код остаётся, ответ на экране сбрасывается — он на старом языке.
- **Перехват клавиш на `window` в фазе capture.** Пока окно открыто, ничто под ним не должно реагировать на клавиши (демка, слайды), а набор в поле должен работать — поэтому `stopImmediatePropagation()` всегда и `preventDefault()` только на обработанных. `Shift+O` в поле кода печатает «O», поэтому закрыть оттуда можно только `Ctrl+Shift+O`. Проверка `e.code`, а не `e.key`: по коду видно, что так клавиша работает и в русской раскладке, где она даёт «Щ».
- **`execCommand("insertText")` для Tab и Enter.** Так правка попадает в стек отмены браузера (`Ctrl+Z` работает); `setRangeText` — запасной путь, если команда не сработала ([20-ai-sandbox.js:1193](../../js/core/20-ai-sandbox.js#L1193)).
- **Голос: ElevenLabs → Piper → Web Speech.** ElevenLabs — тот же голос Milly Maple, что в записях Элис; Piper — офлайн, но только русский и английский; синтез браузера — последний вариант, с темпом и высотой по настроению (`SYNTH_MOOD`). ElevenLabs и Piper живут в `serve.js`, поэтому список пишет у пункта, почему он недоступен, вместо молчания.
- **`runSeq` у каждого запуска.** Голос приходит через секунду-три; поздний ответ прошлого запуска не должен подписать или озвучить следующий ([20-ai-sandbox.js:254](../../js/core/20-ai-sandbox.js#L254)).
- **`hush()` вместо полной остановки звука.** Длинная дорожка (акт интро, тест голоса) ставится на паузу и продолжается после закрытия; короткая реплика и синтез обрываются.
- **Снятие фокуса при закрытии.** Скрытое поле сохраняет фокус и глотало бы клавиши дека ([20-ai-sandbox.js:1176](../../js/core/20-ai-sandbox.js#L1176)).

Таблицы `PRESET_TEXT`, `HEUR` и `SIM_LINES` правятся руками в этом файле; таджикские тексты, по комментарию [20-ai-sandbox.js:155](../../js/core/20-ai-sandbox.js#L155), ждут вычитки носителем. Новый язык — новый раздел в каждой из трёх таблиц плюс локаль в `LOCS`; если модель на нём пишет — запись в `ANSWER_LANG`.

## Подводные камни

- **`RU_ONLY` и промпт связаны текстом.** `systemPrompt()` вырезает фразу `replace`-ом. Правка пунктуации в последней строке `ALICE_SYSTEM_PROMPT` без правки `RU_ONLY` молча оставит в английском промпте оба приказа.
- **Метки шаблона — латиница во всех языках.** Парсер ищет `LUCIDITY`/`ALICE`/`DIAGNOSIS` (и русские синонимы). Если новый `ANSWER_LANG.tail` попросит модель перевести метки, разбор сломается — LUCIDITY станет 50, реплика — весь текст.
- **Новый язык без `ANSWER_LANG` автоматически идёт по таджикской ветке:** модель спрашивают по-русски, вердикт показывается русским, реплику берут из `PRESET_TEXT`/`SIM_LINES` этого языка. Без разделов в этих таблицах — `PRESET_TEXT[loc]` пуст, темы не ищутся, строки берутся из `SIM_LINES.ru`.
- **Три набора границ.** Шкала (`setLucidity`): ≤25 / ≤70 / выше. Настроение голоса (`NeuralVoice.moodOf`) и таджикский банк (`bandOf`): ≤25 / ≤64 / ≤84 / выше. При 65–70 шкала пишет «LOGIC DAMAGE / LEAK», голос нейтральный; при 71–84 шкала «STABILIZED», голос нейтральный, таджикская реплика из `mid`.
- **`job` — общий для всего.** `sendCodeToOllama` ставит отмену в модульный `job`, а не в переданный объект; держится на том, что `analyze` назначает `job` синхронно перед вызовом. Каждый `await` в `analyze` должен сопровождаться проверкой `job === mine`, иначе отменённый запуск допишет вывод в новый.
- **Разбор NDJSON построчно.** Строка без завершающего `\n` в конце потока не разбирается. Ollama завершает каждую строку сама; `serve.js` дописывает `\n` после тела, потому что тело ошибки Ollama после строк очереди может прийти без него ([server.md](server.md#очередь-к-ollama)). Строка, которая не JSON, ломает весь ответ (`JSON.parse` бросает → симуляция, если текста ещё не было).
- **`queued` учитывается только до первого слова** и каждый раз переставляет таймер на `COLD_MS` от момента строки. Пока `serve.js` присылает строки очереди (раз в 2,5 с), запрос не обрывается по пределу первого слова.
- **`lastFailWhy` сбрасывается только в начале `sendCodeToOllama`.** Если следующий запуск ушёл в симуляцию без запроса (опрос дал `offline`), строка источника покажет причину отказа прошлого запуска.
- **Холодная модель определяется по `conn.loaded`**, а он обновляется после ответа без `await`. Если Ollama выгрузила модель сама (истёк `keep_alive`), а `conn.loaded` ещё старый, запрос пойдёт с пределом 7 с и, вероятно, уйдёт в симуляцию; следующий — уже с правильным пределом.
- **Эвристика работает по тексту.** Комментарии `//` вырезаются раньше строк: `"http://…"` в коде отрежет остаток строки вместе с тем, что после литерала. Комментарии Python (`#`) не вырезаются, а `//` (целочисленное деление) в Python режет строку как комментарий. `break`/`return` где угодно в коде отменяют «бесконечный цикл».
- **`Shift+O` при открытом окне закрывает его везде, кроме поля кода** — в том числе в поле «МОДЕЛЬ» (условие `e.target !== code`): заглавную «O» туда не впечатать.
- **Выбор «WEB SPEECH» не запрещает нейроголос.** `speak()` при `synth` не зовёт `NeuralVoice`, но `AliceVoice.speak()` сам отдаёт фразу `NeuralVoice`, если тот подходит к языку (см. [audio.md](audio.md)). Тогда фразу читает ElevenLabs или Piper, `SYNTH_MOOD` не применяется, а строка источника пишет `WEB SPEECH`. Та же ветка после неудачи нейроголоса в режиме `auto` даёт второй запрос к `/api/tts`.
- **Флажок озвучки после «нет голосов».** `paintVoices()` снимает флажок, когда движков нет, но обратно не ставит, когда они появились: до перезагрузки страницы флажок нужно включить руками. В `localStorage` при этом остаётся прежнее значение.
- **Печатная машинка привязана к кадрам.** Не меньше символа за кадр: около 60 символов в секунду на 60 Гц, вдвое быстрее на 120 Гц. В фоне (`requestAnimationFrame` стоит) текст не печатается, пока вкладка снова не станет видимой.
- **`relabel()` срабатывает только при смене языка.** Подписи, добавленные в `build()`, нужно добавить и в `relabel()`, иначе после смены языка они останутся на старом.
- **`presetOf()` сравнивает весь текст.** Пресет с любой правкой, кроме пробелов, считается своим кодом: идёт в эвристику, а при смене языка остаётся как есть.
- **Опрос при открытии идёт и с телефона.** Тихий опрос ограничен этой машиной, но `openBench()` зовёт `probe()` всегда. Если `serve.js` ответил 404 или 403, страница пробует `127.0.0.1:11434` — на телефоне это может вызвать запрос доступа к локальной сети.
- **Окно перекрывает всё, кроме видеоплеера и тостов** (`z-index: 999000`, `styles-media.css:749`). Новое окно поверх полигона должно учитывать, что полигон глушит все клавиши в фазе перехвата на `window`.
