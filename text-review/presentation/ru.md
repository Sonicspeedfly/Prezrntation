## 1. ВЫЗОВ СИСТЕМЕ

_// паралич автокомплита vs реверс-дебаггинг под давлением_

**Автокомплит пишет код быстрее, чем студент успевает его прочитать.** Курсовая собирается из подсказок, проект компилируется с первого раза, диплом защищён. Потом он открывает чужой модуль на сорок тысяч строк, ловит `SIGSEGV` и садится смотреть в экран. gdb он не запускал ни разу, core dump видит впервые. Через минуту он жмёт Tab и ждёт подсказки.

Мы называем это **параличом автокомплита**. На первой работе с него спросят обратный навык — **реверс-дебаггинг под давлением**: взять модуль, который писал кто-то другой, построить гипотезу и проверить её, пока рядом стоит тимлид. В учебном плане такого предмета нет.

### // СТАТУС-КВО :: КАК УЧАТ C++ СЕЙЧАС

```
$ g++ student.cpp -o student
$ ./student
Segmentation fault (core dumped)
$ _
```

- Tab, Tab, Enter — задача закрыта за пятнадцать секунд
- стек трейс не читают: перегенерируют функцию целиком
- «скомпилировалось — значит работает»
- первый настоящий segfault — уже на проде, в три часа ночи

### // TERMINAL: SHATTERED :: КАК У НАС

```
$ ./vault_walk
[ heap ]  resident: 96 KB ─► 1.4 MB
[ panic ] heap exhausted :: bad_alloc
[ ALICE ] нейкон... я тону...
SIGSEGV  ::  segmentation fault
```

- твоя ошибка гасит свет в комнате, где ты стоишь
- компилятор называет строку и причину
- подсказать некому: код чужой, автор — ты сам до амнезии
- чинишь систему, которая тебя не пускает

**Дальше:** 01 — цифры по пробелу в базе · 02 — три уровня и живая демка прямо в этом браузере · 03 — Элис: локальная модель, ноль серверов · 04 — реверс-дебаггинг как предмет · 05 — деньги и роадмап.

### Заметки докладчика

#### speaker notes :: открытие

**Первая фраза:** «Спросите джуна написать функцию — напишет за минуту. Дайте ему чужую сломанную — сядет и будет смотреть».

**Показать левую панель:** так выглядит вся обратная связь, которую студент получает сегодня. Одна строка. Ни причины, ни следующего шага.

## 2. СМЕРТЬ БАЗОВЫХ ЗНАНИЙ

_// ДИАГНОЗ: эпидемия зависимости от автогенераторов кода_

**Код появляется быстрее, чем понимание.** Нажал Tab — получил рабочую функцию. Она собралась, тесты зелёные, работу приняли. Спросить, почему она работает, было некогда; когда она сломается, спрашивать станет поздно.

## 3. ВЫБОР СЛОЖНОСТИ = ВЫБОР ЦЕНЫ

_// ИГРОК САМ РЕШАЕТ, СКОЛЬКО ОН ГОТОВ УЗНАТЬ._

**Сложность ≠ номер главы.** Она _не растёт с уровнем_ — её **выбирает сам игрок до старта.** Один и тот же сюжет — три разных кадра восприятия. Чем глубже залез — тем больше деталей и тем больше расплата.

Каждый режим даёт свой набор инструментов и свой набор страхов:

```
// ascii :: что игрок встретит в каждом режиме
 ┌──────────────────┐   ┌──────────────────┐   ┌──────────────────┐
 │       EASY       │   │      MEDIUM      │   │       HARD       │
 │      Python      │   │       C++        │   │        C         │
 │   все подсказки  │   │   подсказки реже │   │   без подсказок  │
 │   ── мягкие сбои │   │   ▒▒ геометрия   │   │   ╳╳ голос Элис  │
 │   ── без ответов │   │   ── полуправда  │   │   ── вся правда  │
 └──────────────────┘   └──────────────────┘   └──────────────────┘
```

// нажми и попробуй **сам** — это _не запись_, это маленькая отдельная игра в браузере. ты очнёшься **от первого лица** в пустом пространстве, сам дойдёшь до терминала, увидишь загрузку ОС — и дальше уже будешь вводить команды, а призраки придут на твои ошибки.

если на твоём устройстве есть TTS — на HARD Элис заговорит вживую. на EASY/MEDIUM голоса не будет, только текст и глитчи.

### Заметки докладчика

#### speaker notes :: как обыграть это на сцене

**Отдать мышь.** «Это не запись и не видео. Это игра, она уже загружена в этом браузере. Кто попробует?»

Один из жюри (или ты сам) жмёт **▶ ЗАПУСТИТЬ ДЕМО-ИГРУ**. Презентация уходит в боковую часть, открывается отдельный экран: выбор сложности → _пробуждение от первого лица в пустоте_ (вдали глючит дверь, справа горит терминал) → игрок сам доходит до терминала и включает его → загрузка ОС с ядром и графической оболочкой → и только теперь командная строка. Игрок вводит команды. Стоит ему промахнуться — экран рвёт, выползает призрак, на HARD ещё и голос Элис ломается синтезом речи. Ошибка игрока становится событием на экране за секунду, и это ровно тот механизм, ради которого всё сделано.

**Не кликать самому.** Эффект держится на том, что ломают её они.

**Что показать обязательно, если время жмёт:** нажать ▶ ЗАПУСТИТЬ, ничего не исправив, — и показать, что компилятор называет строку и причину, а комната ломается в форме самой ошибки. Тридцать секунд, весь смысл продукта.

_Работает офлайн._ Если на площадке упадёт Wi-Fi — демка не заметит.

## 4. ALICE_CORE :: АВТОНОМНЫЙ ИИ

_// QWEN2.5-CODER ЧЕРЕЗ LLAMA.CPP · $0 СЕРВЕРОВ · РАБОТАЕТ БЕЗ WI-FI_

**Элис работает на _Qwen2.5-Coder_ в формате GGUF**, запущенной через **llama.cpp** прямо на машине игрока. Ключа и аккаунта она не требует, сеть ей не нужна.

**Серверные затраты — $0.** Инференс идёт на CPU игрока, счёт за токены не приходит, и юнит-экономика держится ровной, сколько бы человек ни играло. **Площадка не важна:** хакатон без Wi-Fi, аудитория с фильтрацией, ноутбук жюри без интернета — демка ведёт себя одинаково. **Данные студента остаются на его машине,** поэтому вузу нечего согласовывать: наружу не уходит ни один байт.

### Заметки докладчика

#### speaker notes :: архитектура

**Числа, которые надо назвать вслух:** Qwen2.5-Coder, GGUF Q4_K_M, 4–8 ГБ RAM, CPU без GPU, латентность 2–8 с, серверные затраты — ноль.

**Если сведут к «сэкономили на API»:** локальный запуск снимает ещё два риска. Чужой сервис не упадёт посреди защиты, и вузу не придётся согласовывать передачу студенческих данных наружу. Второй пункт для вуза обычно решающий.

**Честная граница — сказать самому:** в браузерной демке, которую вы сейчас щёлкали, LLM не крутится. Там детерминированная логика и записанный голос. Локальная модель — это сборка на десктопе; браузерная версия существует, чтобы её можно было открыть с QR-кода без установки.

**Если спросят про звук:** Web Audio, единая мастер-шина, реплики режутся фильтрами и дропаутами по состоянию мира. Голос — Piper, 20 МБ, офлайн.

## 5. ТЕРМИНАЛ СОПРОТИВЛЯЕТСЯ

_// ВЗЛОМАЙ СОБСТВЕННЫЙ КОД ЗАЩИТЫ_

**Терминал работает против игрока.** До амнезии Нейкон сам закрыл доступ к критическим модулям. Теперь его собственный код _не пускает его внутрь_, комментарии врут, а имена переменных ничего не значат.

Это и есть **реверс-дебаггинг**. Войти в чужую систему без документации, разобраться, что она делает, починить одно место и не сломать соседнее. С этого начинается стажировка в индустрии; в учебном плане такого предмета нет.

// [VOID_CORRUPTED] найдено в старых логах нейкона
bool verifyAccess(const char* token) {
 unsigned int hash = 0xDEAD;
 while (*token)
 hash ^= (hash << 5) + (*token++) + (hash >> 2);
 return hash == getExpectedHash(); // ← функция не существует.
}

### Заметки докладчика

#### speaker notes :: перевод на язык жюри

**Не говорить** «герой с амнезией взламывает свой код» — это звучит как сюжет игры. **Говорить:** «мы тренируем чтение чужого легаси — навык, с которого начинается первая работа и которого нет в программе».

**Пример, который заходит:** задача про предохранитель. Число выбито на табличке в комнате, генерируется заново на каждый запуск, в файлах образа его нет. Подобрать его нельзя, нагенерировать тем более. Игрок встаёт из-за стола и идёт снимать показание.

**Про амнезию — одна фраза:** это способ сделать «чужой код» своим собственным. Оправдания «мне дали плохой проект» не остаётся.
